# ADR-001: 整理 Agent 不内置 Web 搜索

## 状态

已确认（2026-07-14 讨论）

## 背景

题匠（整理 Agent）的职责是从用户上传的资料中提炼、纠错、去重候选面试题。讨论是否为其引入 web 搜索工具，以解决实时性题目（新框架版本、公司近期面经、行业趋势）的覆盖问题。

## 决策

不为题匠内置 web 搜索工具。

## 理由

### 1. 产品定位：整理用户资料，不是搜索互联网

题匠的工作是"阅读理解 + 出题"，不是"知识检索"。产品主干是：用户上传自己的资料 → Agent 整理成题库 → 审核发布 → 复习。引入 web 搜索会将产品从"整理我的资料"变成"从互联网找题"，这是另一个产品（题库平台），不是个人面试准备工作台。

### 2. 模型参数化知识对面试场景足够

面试题约 80% 是基础不变的知识点（数据结构、算法、系统设计、语言特性），模型的参数化知识完全覆盖。题匠里模型的角色是"理解资料的背景知识 + 生成问题和答案"，不是"知识来源"--答案来源是用户的资料。

### 3. 实时性场景靠用户上传资料解决，更可控

少数实时性场景（新框架、公司面经）的处理方式：

- 用户自己搜索、筛选、上传最新资料。比 Agent 搜网更精准（用户筛选过可信来源）。
- 用户上传的面经质量 > 网上随便搜到的论坛帖子。面试准备场景质量 > 广度。

### 4. 面试准备不是题海战术

用户需要挨个核查、理解每道题，这个手动过程本身就是学习。web 搜索引入的"一键出 50 道题"反而破坏了精读内化的节奏。

### 5. 架构可扩展，现在不加不是技术债

收敛后采用官方 `create_agent` + `BaseTool` + `ToolPolicyMiddleware`。加 web 搜索只需加一个 `WebSearchTool` + 对应 scope，不改架构、不改 middleware pipeline、不改 event projection。是工具配置变更，不是架构变更。

## 替代方案：生成 prompt 给外部 AI 工具

对于确实需要实时性补充的场景，采用 **human-in-the-loop web search**：

1. 题匠分析当前题库覆盖缺口（topics 分布、难度分布）。
2. 生成一段精准的 research prompt（如"搜索 2024 年字节后端面试中关于分布式锁的真题，整理成 Markdown"）。
3. UI 展示 prompt + 复制按钮 + 外部 AI 链接。
4. 用户复制 prompt → 去 ChatGPT/Perplexity/Gemini 搜索 → 拿到结果。
5. 用户人工核查/编辑 → 作为新 source 上传。
6. 题匠正常整理。

**好处**：
- 不重复造轮子（外部 AI 的搜索能力比自建强）。
- 质量闸口在人（用户核查后再上传，输入可信）。
- 零基础设施成本（无搜索 API、无网页解析、无 URL 白名单）。
- 产品边界清晰（题匠 = 整理你给我的东西）。

**落地时机**：不在 R2（复习闭环优先），可作为 R7（知识库与本地产品化增强）的 UX 增强或独立小迭代。

## 如果未来要加 web 搜索，加在哪

不加在题匠（整理环节），加在：
- **复习 Agent**（R2/R6）：用户答完一题，Agent 可搜索补充最新最佳实践。
- **模拟面试 Agent**（R6）：Agent 搜索公司最新面经，出更贴切的题。

这些场景里 web 搜索是**补充**（辅助学习），不是**来源**（题库仍来自用户资料）。

## 讲解口径

> 刻意不在整理 Agent 内置 web 搜索。三个原因：第一，面试准备不是题海战术，用户需挨个核查理解，手动过程是学习的一部分；第二，最新模型能解决 99% 的常规面试题，模型在题匠里是"理解资料的背景"不是"答案来源"；第三，实时性场景靠用户上传最新资料解决，或生成 prompt 让用户用成熟 AI 工具搜索后人工核查再上传--比自建搜索更靠谱，零基础设施成本。
