# ADR：历史复盘检索 Agent 与证据边界

- 日期：2026-08-04
- 状态：Accepted

## 决策

Workspace 历史复盘检索采用“有界 Agent + 确定性检索 + 不可变结果集快照”的组合，而不是自由 ReAct 或模型直接扫描长文档。

Agent 只负责将自然语言解释为结构化检索计划，并在冻结结果集上进行总结和报告生成。程序负责语料范围、完整扫描、过滤、计数、排序、分页、引用校验和来源定位。

即时总结不持久化为正式业务文档；总结报告保存为独立、版本化、Workspace 私有 Artifact，并绑定生成时的 Search Set 和题目 ID。

## 原因

该能力同时要求自然语言体验和“所有结果”的可证明完整性。自由 ReAct 可以改善表达，但无法稳定证明已经扫描全部分页，也容易重复搜索、漏结果或在上下文压缩后丢失“这些问题”的指代。

不可变 Search Set 将查询条件、结果 ID、稳定顺序和来源快照固定下来，使后续“总结一下”“只看回答不好的”“生成报告”等操作始终引用同一证据集合。

## 拒绝的方案

### 自由 ReAct 扫描全部复盘

拒绝。调用次数、分页完整性和成本不可控；模型上下文不能承担 Workspace 搜索索引。

### 只做全文搜索，不提供 Agent

拒绝。用户需要自然语言拆解、项目别名理解、跨结果聚合和连续追问。

### 把能力塞入单场“讨论与纠正”

拒绝。单场讨论具有纠正写入边界，跨复盘检索会混淆来源、状态和纠正目标。

### 首版引入向量数据库

拒绝。当前本地 Workspace 数据量、部署方式和可解释性要求不足以证明新增基础设施的必要性。首版先积累词法漏召回样本。

## 代价

- 需要维护 Search Set、Result 和 Report 三类新状态；
- 词法检索无法保证同义词语义召回，需要 Agent 提供别名并保留成熟度声明；
- 报告生成需要 Map-Reduce 和引用校验，流程比单次大 Prompt 更复杂；
- 原始复盘被清除或删除时，需要维护引用可用性。

## 重新评估条件

满足任一条件时重新评估语义检索或外部索引：

- 真实用户检索日志中，经过项目别名扩展后仍出现稳定漏召回；
- 单 Workspace 正式题目超过本地词法扫描的交互预算；
- 需要跨设备或服务端多人共享索引；
- 报告引用需要跨题库、Knowledge 和外部资料统一排序。
