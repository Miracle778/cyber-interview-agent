# 复盘讨论上下文与 Tool 调用恢复边界

日期：2026-08-03

状态：已接受

## 背景

面试复盘讨论 Agent 会接收用户当前选中的题目，并且可以调用 7 个有界、只读 Tool。第一版实现把最近 12 条产品对话消息序列化后，整体放进一个 JSON 格式的 `HumanMessage` 中。虽然这样可以让当前请求携带历史记录，但也产生了三个 Harness 问题：

1. 消息级上下文压缩无法拆分这段嵌套历史，也无法选择性保留其中的完整轮次；
2. 固定消息条数不能约束 Token，少量超长回复仍可能超过模型上下文预算；
3. 模型无法区分已经完成的历史问答、执行失败的用户消息和尚未得到回复的用户消息。

当前业务 Tool 都是本地、有界、只读查询。它们可以安全重试。为了这些低延迟、无业务副作用的 Tool 引入持久化的调用中恢复，会额外增加 Checkpoint 生命周期管理和 SQLite 并发写入成本，收益不足以覆盖复杂度。

## 决策

### 一、产品对话历史与 Agent 运行状态分开保存

- 用户与助手的产品消息继续作为跨运行的持久对话来源。
- `selectedQuestionId`、当前用户消息和复盘 ID 在模型开始处理前，作为 Execution 输入持久化。
- 每次调用从产品消息中装配最近的**完整问答轮次**，并恢复为独立的 `HumanMessage` 和 `AIMessage`。
- 当前请求始终作为最后一个 `HumanMessage`，其中只包含当前文字、选中题目锚点和上下文裁剪统计。
- 内部 `AIMessage.tool_calls`、对应的 `ToolMessage` 和最终结构化响应只属于单次 Agent State 和本地 Trace 证据，不投影到用户可见的产品对话。

### 二、按 Token 预算选择历史，不再按消息条数截取

- 使用独立历史预算，从最新的完整问答轮次开始，按从新到旧的顺序选择历史。
- 历史预算根据已配置的复盘讨论最小上下文窗口计算，并限制在 1,000～8,000 Token。
- 每个问答轮次作为原子单元加入或舍弃，不允许只保留助手回复，也不允许把尚未回复的用户消息带入下一次讨论。
- 当前请求携带 `includedCompleteTurns` 和 `omittedCompleteTurns`，让模型知道自己是否看到了全部对话历史。
- 本阶段直接省略超出预算的旧轮次，不把它们转换成持久化语义摘要。复盘事实必须通过当前领域的只读 Tool 重新读取，不能依赖可能已经过时的聊天摘要。

### 三、把 Tool 请求与结果视为不可拆分的安全片段

- 上下文压缩只在模型节点执行前运行，不会与正在运行的 Tool 节点并发执行。
- 已完成的 `AIMessage(tool_calls)` 和对应 `ToolMessage` 共同构成一个安全片段。
- 继续使用 LangChain 官方的安全切分逻辑；当切分点落在 `ToolMessage` 上时，切分点必须回退到发起对应 Tool 调用的 `AIMessage`，不能留下孤立 Tool 结果。
- 上下文编辑可以把较旧且已经完成的 Tool 返回正文替换为占位内容，但必须保留 Tool Call ID，并保留最近 3 条 Tool 结果正文。
- 用户在 Tool 执行期间停止任务时，取消整个本次调用，不保存半截助手回复。用户重试时，可以安全地重新执行这些只读 Tool。

### 四、复盘讨论使用独立运行预算

复盘讨论使用独立预算配置：

- 每次运行最多调用模型 12 次；
- 每次运行最多调用业务 Tool 6 次；
- 超过 Tool 调用预算后，向模型返回有界 Tool 错误，不立即把整个 Execution 标记为失败；
- 如果模型连续输出没有实际进展的内容，继续由共享运行时的 No Progress Guard 终止循环。

## 未采用的方案

### 一、立即持久化完整 LangGraph Tool 循环

当前不采用。现有 Tool 全部为只读查询，没有必须防止重复执行的业务副作用。完整持久化需要新增 Checkpointer、Checkpoint 保留策略、进程重启对账逻辑和更多 SQLite 写入者，复杂度明显高于当前收益。

### 二、立即持久化模型生成的对话摘要

当前暂缓。语义摘要可能保存已经过时的题目分析或画像事实，而且这类过时信息很难被程序发现。当前实现优先保留有界的近期讨论意图，并通过 Tool 读取权威领域状态。

如果后续真实长对话 Trace 证明省略旧轮次会明显降低回答质量，可以再引入只保存用户讨论目标、不复制领域事实的持久化意图摘要。

### 三、继续保留最近 N 条消息

不采用。消息数量不能约束 Token，而且可能从逻辑问答轮次中间截断。

## 后续升级边界

如果复盘讨论 Agent 后续增加网络 Tool、浏览器 Tool、长耗时 Tool 或任何写 Tool，必须重新评估本决策。届时需要升级为：

- 持久化 `ToolInvocation` 台账，保存输入摘要、状态和结果引用；
- 写操作使用幂等键和领域 Receipt；
- 引入持久化 Checkpointer 和进程重启对账器；
- 恢复时复用已经完成的结果，安全重试只读操作，绝不盲目重复非幂等写操作。

## 验证标准

- 当前输入不再包含嵌套的 `recentConversation` JSON；
- 最近完整问答轮次以独立角色消息传给模型；
- 被选中的历史轮次不超过配置的 Token 预算；
- 未完成的历史用户消息不会进入下一次讨论；
- 上下文压缩不会拆开 `AIMessage(tool_calls)` 与对应 `ToolMessage`；
- 讨论运行中被停止时，不会持久化半截助手回复。
