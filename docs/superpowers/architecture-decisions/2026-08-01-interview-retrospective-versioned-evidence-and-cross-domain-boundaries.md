# 面试复盘版本证据与跨领域写入边界

日期：2026-08-01

状态：Accepted

## 背景

面试复盘同时接触求职目标、原始转写、用户回答、统一画像、项目讲解、题库和 Knowledge。如果把模型总结直接写入任一既有领域，系统将无法区分用户原话、模型推断和用户确认事实，也无法在用户修正说话人或问题后可靠重算。

该阶段还需要处理长文本后台运行、渐进逐题结果、停止恢复、局部重算和原文单独清除。Agent checkpoint、JSONL Trace、Knowledge 文档和聊天消息都不足以单独承担这些业务状态。

## 决定

### 1. 新增独立复盘领域，但不新增 Runtime

面试复盘领域拥有源版本、整理版本、问题单元、分析版本、缺口、行动项和跨领域候选。它复用现有 Workspace Runtime、Session、Execution、Checkpoint、Event、Trace、HITL 和 Provider 配置。

领域表是业务权威来源；Checkpoint 负责执行恢复；JSONL Trace 负责诊断；Knowledge 只保存用户选择发布的文档。

### 2. 求职目标是强制父级

每场复盘必须引用一个 Job Target。一轮面试对应一场复盘，多轮在目标下聚合。目标永久删除时删除复盘私有资源，但已确认写入统一画像、项目讲解、题库和 Knowledge 的资产继续存在。

### 3. 原文、整理和分析采用不可变版本链

`SourceVersion → CleanupVersion → AnalysisRun/AnalysisVersion` 各自不可变。Retrospective 只保存 active 指针。新版本运行失败时不破坏旧 active 结果。

用户修正单题时创建局部分析版本并重建整场聚合；修改说话人或跨题边界时创建新的 CleanupVersion。禁止原地覆盖历史分析。

### 4. 问题来源是下游权限边界

原始问题和推断问题必须分别保存。未确认推断问题可以生成临时分析草稿，但不能形成正式整场结论、题库候选或岗位风险。用户决定是确定性领域命令，不由 Agent 自行确认。

### 5. 模型输出始终是候选

题目、画像、项目经验、总结和行动建议先进入复盘候选。正式写入分别调用 Review、Profile、Job Target/Project Narrative 和 Knowledge 的领域接口，并保存幂等 Receipt。模型不获得这些领域的写 Tool。

### 6. 分析处理与持续对话分离

每场复盘拥有一个系统可见的分析 Session 和一个用户可见的持续对话 Session：

- 分析 Session 保存多次整理、整场分析和局部重算 Execution；
- 对话 Session 保存解释、追问和修正建议；
- 对话不能直接覆盖分析版本；
- 用户确认修正建议后，由 application service 调度新的分析 Execution。

这种分离避免聊天消息成为分析状态源，也避免后台处理事件污染面向用户的对话历史。

### 7. 渐进工作项单写者提交

问题提取和逐题分析可以并发调用 Provider，但最终问题顺序、逐题版本、整场汇总和候选去重由单一 reducer/领域事务提交。每个工作项有稳定 fingerprint 和 attempt receipt，停止只阻止领取新工作。

### 8. 原文可以清除，结论降级保留

用户可清除原始文本。清除同时移除保存的原文摘录和可重读 Artifact，保留哈希、结构化结论、用户决定和跨领域 Receipt。清除后该版本永久失去重新整理和重新分析能力，系统不得尝试从 Trace 或模型响应恢复正文。

### 9. 不做首版自动脱敏和联网核验

首版将用户确认的整理版本与可见上下文发送给已配置 Provider，不承诺自动识别人名或商业敏感内容。技术正确性区分内部证据、模型通用判断和信息不足；不能把模型判断伪装成外部核验。

### 10. Knowledge 发布是选择性投影

完成的复盘无论是否发布都保存在复盘领域。Knowledge 新增 `interview_retrospective` 文档类型，只包含用户选择的面试信息、已确认问题、结论、经验、行动项和稳定链接；完整转写、未确认推断和对话全文不进入文档。

## 否决方案

### 只保存一份 Markdown 报告

否决。无法支持逐题局部重算、候选决定、运行恢复、原文清除和跨领域 Receipt。

### 把完整复盘存在聊天消息或 Checkpoint

否决。消息和 Checkpoint 不提供领域版本、删除语义和跨领域一致性，也不适合作为长期查询源。

### Agent 直接修改题库和画像

否决。无法维持用户确认、证据所有权、版本冲突和幂等写入边界。

### 用 JSONL Trace 恢复被清除原文

否决。Trace 是诊断数据，不是业务备份；用户清除正文时相关业务正文和可重读诊断正文必须按保留策略清理或变为不可访问。

### 首版引入音视频、自动脱敏或联网研究

否决。三者分别引入媒体处理、隐私识别和外部来源可信度的新边界，都会稀释首版“文字复盘到可行动资产”的闭环。

## 结果

正向结果：

- 原话、整理、推断、模型判断和用户确认能够长期区分；
- 失败重试和局部重算不会破坏旧报告；
- 下游资产继续由各自领域维护；
- 原文删除可以执行而不伪造可追溯性；
- 运行中心、业务页面和高级诊断继续共享同一 Runtime。

代价：

- 需要新增一组领域表和版本指针；
- 跨领域候选必须维护 adapter 与 receipt；
- 用户修改说话人或问题时，页面必须解释版本和重算影响；
- 清除原文后部分报告会失去来源摘录，页面必须持续展示降级状态。
