# 面试复盘修订稿证据边界

日期：2026-08-02

状态：Superseded

由 `2026-08-02-clean-transcript-artifact-and-internal-window-boundary.md` 取代。本文仅保留旧 Segment/Correction 方案的历史决策背景。

## 背景

录音转写包含错别字、同音错误、断句问题和技术词误识别。直接分析原文会传播错误；直接用模型改写稿覆盖原文，又会失去用户真实表达、误改审计和下游证据归属。

现有复盘已经采用 `SourceVersion → CleanupVersion → AnalysisRun` 的版本链，并在 Cleanup 阶段执行长文本分窗、说话人整理和用户确认。需要决定文字修订由谁拥有、何时确认，以及分析读取哪一层文字。

## 决定

### 1. SourceVersion 始终保存不可变原文

模型和用户都不能原地修改 SourceVersion。原文只在用户执行“清除原文”时按现有删除语义移除。

### 2. CleanupVersion 同时拥有段落整理和文字修订

不新增独立 CorrectionVersion 或第二套长文本任务。Cleanup Agent 在同一窗口内完成说话人、段落和文字修订，Reducer 一次性归并。

### 3. 修订使用独立 CorrectionRecord 审计

SegmentRecord 保存当前采用文字和原文 offset；CorrectionRecord 保存原文、建议、风险、原因和用户决定。低风险修改可以自动接受，高风险修改必须明确接受、保留原文或手动修改。

### 4. 对话轮次可以恢复，但不得伪造证据

模型可以在同一稳定原文单元内根据问答语义恢复说话人切换。单元拆成多个轮次时，每个轮次必须携带逐字原文片段，程序验证所有片段顺序拼接后与不可变原文完全相同，并据此计算绝对位置。模型不得在 Cleanup 中补写录音缺失内容、完整问题、答案或事实。

候选人单边录音中能够从回答直接反推的问题，由后续问题提取阶段保存为 `origin=inferred`，绑定回答证据并等待用户确认；它不能进入 CleanupVersion 冒充录音原话。歧义术语、否定、数字、主体和技术结论变化仍按修订风险规则处理，无法给出安全建议时保留原文。

### 5. 分析只读取确认后的修订文字

AnalysisRun 只能引用 confirmed CleanupVersion，并读取其 SegmentRecord.body。问题、回答和结论仍通过段落与原文 offset 回溯 SourceVersion 和 CorrectionRecord。

### 6. 原文清除覆盖所有正文副本

清除 SourceVersion.body 时，同时清除 CorrectionRecord 的原文、建议正文和可重读 Trace 正文。可以保留修改类型、风险、决定、哈希和结构化结论，但不能保留绕过用户删除意图的正文副本。

## 否决方案

### 模型修订稿直接覆盖原文

否决。无法识别误改、解释证据或恢复用户真实表达。

### 单独增加 CorrectionVersion 长文本流水线

否决。会重复切片、Provider 调用、恢复状态和用户确认；说话人信息缺失还会降低断句与代词修正质量。

### 只修改 Cleanup Prompt，不保存修改记录

否决。下游无法区分用户原话、自动修正和手动修订，也无法实现高风险确认门禁。

### 使用题库答案或画像结论帮助修订

否决。会把标准答案和历史模型判断污染到用户原话，制造看似准确但不存在于录音的内容。

## 结果

正向结果：

- 分析输入更准确，同时保留真实原文和修改证据；
- 说话人、断句和词汇修订可以共享同一上下文；
- 现有长文本恢复和窗口拆分机制可以继续使用；
- 高风险误改在进入分析和下游资产前受到用户确认约束。

代价：

- CleanupVersion 的领域合同和确认条件更复杂；
- 需要新增修订记录、差异展示和决定 API；
- 原文清除必须覆盖更多正文副本；
- 真实 Provider 验收需要衡量误改率和用户撤销率。
