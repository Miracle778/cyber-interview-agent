# 阶段 Learning 掌握包模板

每个主要产品切片在 `docs/learning/<stage>/` 创建以下七份本地文件。材料必须基于最终代码、真实验证和实际发生的故障；禁止用通用教程、虚构故障或单个 README 代替。

## `overview.md`

必须包含：

- `## 学习基线`：阶段完成提交、适用代码版本和前置知识；
- `## <阶段> 解决的问题`：用户问题、工程问题和本阶段边界；
- `## 如何使用本掌握包`：推荐阅读与实践顺序；
- `## 当前边界`：尚未覆盖和后续演进；
- `## 掌握标准`：用户能够解释、追踪、审阅或调试什么。

## `architecture.md`

必须包含 `## 总体结构`，说明组件职责、调用方向、状态所有权、信任边界和关键设计取舍。架构图或流程图必须与最终代码一致。

## `code-walkthrough.md`

至少包含一个以 `## 链路` 开头的章节。每条链路从真实入口开始，沿函数、状态和持久化边界走到可见结果，并解释关键分支为什么存在。

## `failure-journal.md`

每个二级章节只记录真实发生的故障：现象、错误假设、根因、修正、验证证据和如何提前发现。若阶段没有真实故障，应明确记录这一事实并引用验证记录，不能虚构案例。

## `interview-questions.md`

使用三级标题写问题，并给出可追问的答案。问题应覆盖设计理由、替代方案、失败路径、安全或一致性边界，以及如何用证据证明实现有效。

## `presentation-script.md`

必须包含：

- `## 3 分钟版本`：问题、核心方案、结果和边界；
- `## 10 分钟讲解提纲`：架构、关键链路、取舍、故障和验证。

## `exercises.md`

必须包含：

- `## 主练习`：能够证明 Explain、Trace、Review、Debug 或实现能力的任务；
- `## 降级形式`：时间不足时可改做的代码审阅、故障定位、流程图或伪代码练习；
- `## 练习状态`：未开始、进行中、已完成和证据位置。

练习不阻塞产品开发、提交、合并或下一阶段。未完成练习记录为理解债务，不记为产品缺陷。

## 阶段关闭检查

1. 七份文件都基于最终代码，无未完成占位符。
2. 对照上一阶段同类型材料，内容深度没有明显退化。
3. failure journal 只包含真实故障或明确的“本阶段无真实故障”记录。
4. 运行 `scripts/check_stage_docs.py`，并在最终汇报记录结果。
