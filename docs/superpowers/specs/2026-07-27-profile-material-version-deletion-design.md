# 简历单版本永久删除设计

## 1. 目标

在保留现有“永久删除整份简历”能力的同时，允许用户永久删除某一份简历材料中的单个版本。

版本级删除只处理目标 `MaterialVersion`，不得清理同一材料的其他版本，也不得影响其他简历材料。

## 2. 产品语义

页面明确区分两种危险操作：

- `删除当前版本 vN`：只永久删除当前选中的版本；
- `永久删除整份简历（含 N 个版本）`：沿用现有材料级删除流程。

版本级删除遵循以下规则：

1. 非当前版本可直接进入版本删除影响预检；
2. 当前版本可以删除，但必须从剩余版本中选择新的当前版本，默认推荐最新的剩余版本；
3. 材料只剩一个版本时，不提供版本级删除，提示使用整份简历删除流程；
4. 当前 Workspace 存在任何 `pending` Claim Proposal 时，所有简历版本都禁止删除，并引导用户先处理“待确认”内容；
5. 阻断不依赖 Proposal 是否直接引用目标版本。待确认信息可能跨版本复用历史 Evidence，不能用当前可见的直接引用关系推断删除安全；
6. 删除不可撤销，归档不能替代版本级隐私清除。

## 3. 删除影响与数据边界

删除预检只计算目标版本关联的：

- 原文件与提取文本；
- Evidence；
- Claim Version 支持关系；
- 发布选择或活动发布依赖；
- Workspace 待确认 Proposal 总数（仅用于版本删除安全阻断，不纳入目标版本清理范围）；
- 当前版本替换要求。

执行删除时：

- 清理目标版本的 `storage_ref`、`text_ref` 和文件名正文；
- tombstone 目标版本的 Evidence 正文；
- 不修改同材料其他版本及其 Evidence；
- 已确认 Claim 仍有其他有效 Evidence 时保持 `supported`；
- 已确认 Claim 失去全部有效 Evidence 时，用户必须在预检中选择：
  - 保留，并标记为 `unsupported`；
  - 同时删除；
- 若目标版本是当前版本，在同一事务内把材料的 `current_version_id` 切换为用户选定的剩余版本；
- 版本记录保留无敏感正文的 tombstone，用于审计和防止旧引用失真；
- 材料的 `version_count`、当前版本和列表投影必须同步刷新。

## 4. API

新增：

```http
POST /api/profile/material-versions/{versionId}/deletion-preview
POST /api/profile/material-versions/{versionId}/permanent-delete
```

两条请求都必须携带 `workspaceId`。执行请求还必须携带：

- `deletionPlanId`；
- 目标版本的乐观锁版本；
- 精确的 Claim 处理选择；
- 目标版本为当前版本时的 `replacementVersionId`；
- 活动发布处理选择；
- `Idempotency-Key`。

预检计划有过期时间。执行前重新计算影响；若新增任意待确认 Proposal，返回稳定的版本删除阻断错误；Evidence、Claim、发布依赖、目标版本或替换版本发生其他变化时返回影响冲突，不执行部分清理。

## 5. 前端交互

版本操作菜单增加 `删除当前版本 vN`。

入口状态：

- Workspace 存在待确认建议：所有版本入口禁用，并显示“请先处理全部 N 条待确认信息，再删除任一简历版本”；
- 只剩一个版本：禁用，并显示“这是唯一版本，如需清除请删除整份简历”；
- 其他情况：打开版本删除影响预检弹窗。

弹窗结构：

1. 标题与不可恢复说明；
2. 受影响原文、Evidence 和画像资料数量；
3. 当前版本删除时的新当前版本选择器；
4. 受影响 Claim 使用可读标题展示，并可展开查看确认内容及目标版本/其他版本的依据数量；
5. 通过复选框建立显式选择集，支持全选和仅对所选项批量设置处理方式，未选项保持原决定；
6. 输入 `删除此版本` 后才能提交；
7. 固定头部和底部，内容区独立滚动，不超过视口。

删除成功后：

- 关闭弹窗；
- 刷新材料及版本列表；
- 选中新的当前版本，或选中仍存在的最近版本；
- 显示明确成功反馈，不跳离“简历与来源”页。

## 6. 错误与恢复

- 待确认建议在预检后出现：返回冲突并刷新页面，提示先处理待确认内容；
- 替换版本被删除或状态变化：返回冲突，要求重新选择；
- 活动发布无法撤销：安全失败，不删除文件；
- 部分领域写入使用 Item Receipt；重试不得重复清理已完成项目；
- 前端保留用户已选择的 Claim 处理方式，冲突后只刷新失效数据。

## 7. 验收标准

1. 删除非当前 v1 后，v2、v3、当前版本及其 Evidence 均保持不变；
2. 删除当前 v3 时，必须选择 v1 或 v2，事务完成后选中的版本成为当前版本；
3. 唯一版本没有版本级删除入口；
4. 任一版本或其他简历材料存在待确认建议时，所有版本均无法预检或执行删除；
5. 预检完成后新增待确认建议，执行仍返回稳定的 `profile_material_version_has_pending_proposals`，目标版本保持不变；
6. 目标版本删除后，仅由其支持的 Claim 按用户选择删除或转为依据不足；
7. 并发产生 Proposal、修改 Claim 或切换当前版本后，旧删除计划返回冲突；
8. 重复提交同一幂等请求不会重复清理；
9. 现有整份简历永久删除流程保持不变；
10. 桌面和窄屏弹窗不超出视口，危险操作文案明确。
