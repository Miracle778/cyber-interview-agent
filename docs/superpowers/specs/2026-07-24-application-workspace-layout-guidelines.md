# 应用工作台页面设计准则

日期：2026-07-24

状态：Accepted

适用范围：Cyber Interview Agent 的桌面与移动 Web 页面。

## 1. 页面类型必须显式区分

每个页面在设计和实现前必须声明为以下一种类型：

- **阅读页**：用户以顺序阅读为主，例如“我的画像”。允许页面自然纵向滚动，正文保持可读行宽。
- **工作台页**：用户在列表、详情和操作之间反复切换，例如“待确认”“简历与来源”“题目库”和 Agent 会话。桌面端必须占满剩余视口，由明确区域负责滚动。

不得用阅读页的自然文档流实现桌面工作台，也不得为短阅读内容制造多个嵌套滚动区。

## 2. 桌面工作台布局

- 应用外壳、页面外壳、工作台和各 Grid/Flex 中间层必须形成连续的高度传递，并设置 `min-height: 0`。
- 页面标题、一级页签和工作台工具栏不随内容滚出视口。
- 工作台使用 `grid-template-rows: auto minmax(0, 1fr)` 或等价结构。
- 新增工作台必须复用 `TaskWorkspace` 与 `TaskWorkspacePane`（或明确的共享等价物）；禁止依靠把新页面类名追加到父容器选择器来获得高度和滚动，否则新增子页会再次出现内容裁切。
- 列表、详情正文和长文阅读器分别声明滚动所有权，使用 `overflow-y: auto`、`overscroll-behavior: contain` 和稳定滚动槽。
- 桌面工作台不得把 `document.documentElement.scrollHeight` 撑出可用视口。
- 同一层级最多存在两个并列滚动区；禁止无意义的滚动套滚动。
- 主操作区固定在所属面板底部，并为滚动内容预留底部空间。

## 3. 主从工作台

- 20 条以上可选择内容优先使用“队列 + 详情”而不是卡片瀑布流。
- 队列项展示选择控件、类型、标题、一句话摘要、来源和异常状态。
- 详情展示最终结果预览、变化、原因、来源和操作，不展示内部字段表或原始 JSON。
- 桌面端队列建议宽度为 `280–360px`，详情消费剩余空间。
- 移动端转换为“列表 → 独立详情”的两级导航，不横向挤压双栏。

## 4. 长任务反馈

- 超过 1 秒的操作必须展示当前真实阶段；超过 10 秒时同时展示实时耗时和可恢复说明。
- 不得用无法由后端事实支持的百分比。
- 长任务必须说明已完成并持久化的成果、当前动作、失败后从哪里继续。
- 允许用户离开当前页；在同一产品工作区持续显示紧凑后台状态。
- 普通模型调用使用“停止 / 继续”而非“暂停 / 恢复同一调用”。停止后保留已上传、已解析和已脱敏成果，继续时从最后一个持久阶段重新执行。
- 完成后给出明确下一步，例如“已生成 27 条建议 · 去确认”。

## 5. 批量决策

- 批量页面必须提供逐项复选框、全选当前筛选范围、清空选择和固定批量操作栏。
- “一键确认”只作用于当前筛选范围内可安全确认的条目。
- 冲突、缺少稳定身份或缺少必需来源的条目不得进入一键确认集合，必须单独核对。
- 提交前显示分类统计和排除数量；部分失败时只保留失败项，不重复成功项。
- 批量忽略和批量确认必须使用不同视觉层级，且不能只用颜色表达含义。

## 6. 私有文档阅读

- 完整文档使用独立阅读器，不在小抽屉或孤立原文块中阅读长内容。
- 阅读器包含目录、格式化正文、版本信息、来源定位、高亮和返回路径。
- 用户默认查看本地原文，并可切换到模型使用的脱敏版本。
- 原文与脱敏内容都必须经过 Workspace 归属校验，不生成公开 URL。
- Agent、模型请求和日志只使用脱敏内容。
- “查看依据”进入同一阅读器并定位到对应段落。

## 7. 响应式与可访问性

- 固定验收宽度：390、768、1024、1440。
- 390px 不允许页面级横向滚动；主要触控目标不小于 44px。
- 768px 与 1024px 必须验证主任务可达，不能只检查是否换行。
- 1440px 必须检查空白比例和可读行宽，不能让次要栏挤压主内容。
- 状态必须同时使用文字和图标；所有图标按钮具有可访问名称。
- 键盘焦点顺序与视觉顺序一致；面板切换后焦点进入新内容标题。
- 动效仅用于状态连续性，持续 150–300ms，并尊重 `prefers-reduced-motion`。

## 8. 时间与耗时

- 数据库和 API 的时间戳以 UTC 为权威；所有面向用户的日期、时间和消息时间统一显示北京时间（`Asia/Shanghai`），不得依赖用户操作系统或浏览器所在时区。
- 前端必须复用 `frontend/src/shared/time.ts`。SQLite `CURRENT_TIMESTAMP` 产生的 `YYYY-MM-DD HH:mm:ss` 无时区字符串必须先按 UTC 解析，再转换为北京时间；业务组件禁止直接对 API 时间调用 `new Date(value)`、`Date.parse(value)`、`toLocaleString()` 或自行创建 `Intl.DateTimeFormat`。
- 日期、时间、日期时间只允许改变展示精度，不允许改变时区口径。仅包含 `YYYY-MM-DD` 的业务日期（例如用户填写的计划日期）按原值展示，不得当作时间戳偏移。
- “耗时”是两个时间点的差值，不做时区格式化；运行中由持久化 `startedAt` 与前端秒表计算，终态使用 `finishedAt` 冻结。不得把耗时误显示成时刻，也不得每秒请求后端刷新。
- 本地 JSONL 等人工诊断产物保留 UTC 权威字段，并同时提供北京时间可读投影；排序、关联和恢复继续使用 UTC 字段。
- 新增时间展示至少覆盖两类回归：带 `Z`/offset 的 ISO 时间，以及 SQLite 无时区 UTC 时间。代码评审应确认共享时间工具之外没有新增 API 时间格式化实现。

## 9. 选择框与筛选选项

### 9.1 统一组件与视觉

- 业务页面必须复用 `frontend/src/shared/ui/SelectControl.tsx`；不得直接新增裸 `<select>` 或在业务模块内复制选择框边框、箭头、焦点和禁用态样式。现有共享组件无法覆盖的交互，应先扩展共享组件并补回归测试。
- 默认使用共享的 `sm` / `md` 尺寸、图标、浮动标签、悬停、焦点和禁用语义。业务页面只负责布局宽度，不得用局部 CSS 改出另一套控件外观。
- 选择框必须具有可访问名称。可见标签优先使用关联的 `<label>`；仅在界面已有等价标题时使用 `aria-label`。
- 控件在加载、空数据和不可用时必须提供明确文案与禁用态，不得保留一个看似可操作但没有有效选项的空框。

### 9.2 选项必须是用户概念

- 选项只呈现用户能理解、能预测结果且确实产生不同操作结果的业务维度；不得把数据库枚举、事件类型、内部状态机节点或 Tool 名直接暴露给用户。
- 多个内部状态如果对用户意味着同一件事，必须聚合为一个用户化选项。例如排队、等待输入和等待确认可以归入“等待处理”；取消和暂停可按产品语义归入“已停止”。
- 不得为了展示后端“有多少状态”而增加用户无法区分的选项。新增选项前必须回答：用户选择它以后，列表或操作结果与现有选项有什么实际不同？
- “全部”必须说明所处维度，例如“全部 Agent”“全部状态”“全部来源”；不要在同一区域堆叠多个无法辨认维度的“全部”。
- 选项顺序必须稳定：先“全部”，再按用户任务流程或固定业务优先级排列；不得随接口返回顺序、当前数量或刷新结果跳动。

### 9.3 筛选集合不得被自身条件裁掉

- 筛选项、标签栏和分面计数必须基于当前页面的父级查询范围计算，但计算某一维度时必须排除该维度当前选中的条件。选择某个 Agent 后，其他 Agent 选项仍然存在；选择某个状态后，其他状态选项仍然可见。
- 当前选择只负责改变选中态和目标内容，不得让同级选项消失、重排或变成无法取消的单向入口。再次选择或使用“全部”必须能恢复未筛选状态。
- 选项来源不得只取当前分页结果。需要跨页稳定展示时，后端必须返回独立的分面集合或汇总计数。
- 零结果选项是否保留由页面任务决定，但同一次交互内必须稳定：如果初始可见，就不能仅因用户选中了同维度的另一项而消失。
- 分面数量、状态卡数量和实际筛选语义必须来自同一套聚合规则，禁止界面显示用户化状态、接口却按单个内部状态过滤。

### 9.4 验收要求

新增或修改选择框至少验证：

```text
默认、悬停、键盘焦点、禁用和窄屏样式一致
选项具有可访问名称，键盘可完成打开、选择和清除
选择任一选项后，同级选项集合与顺序保持稳定
深链接、刷新和分页后仍能显示当前值及完整同级选项
用户化选项、计数和实际查询结果语义一致
```

## 10. 自动与人工门禁

工作台页面至少验证：

```text
document scrollHeight <= viewport height
每个指定滚动区 scrollHeight >= clientHeight
核心操作按钮在不滚动整个页面时可达
390/768/1024/1440 无横向溢出
长内容不会遮住固定操作栏
键盘可完成选择、打开详情和提交
```

代码评审必须回答：

1. 这是阅读页还是工作台页？
2. 谁拥有纵向滚动？
3. 长内容、空数据、运行中和失败时高度是否仍成立？
4. 固定元素是否为正文预留空间？
5. 是否复用了共享工作台外壳，而不是重新计算 `100dvh - Npx`？
6. 所有用户可见时间是否经过共享工具转换为北京时间，耗时是否按时间差计算？
7. 所有选择框是否复用 `SelectControl`，选项是否为稳定的用户化业务概念，而不是内部枚举或当前分页结果？
