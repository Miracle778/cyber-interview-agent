# 设置页体验重构设计

## 1. 背景与决策

当前设置页按“工作区、Provider、模型用途绑定、Runtime、自检、安全检查、人工确认”的顺序纵向平铺完整卡片。所有功能同时占据页面，缺少配置顺序、当前状态和主次关系；随着 R2 前基础能力继续增加，页面长度和理解成本会持续上升。

本切片把设置页重构为“配置概览 + 分组导航 + 单内容面板”。默认展示概览，用户按任务进入工作区、模型服务或运行诊断。现有后端接口、Provider/模型绑定逻辑、Runtime、安全检查和 HITL 状态机保持不变。

`ui-ux-pro-max` 的设计结论用于约束实现：配置流程采用渐进披露；每个视图只保留一个最高强调级主操作；状态同时使用文字、图标和语义色；交互目标不小于 44px；桌面、平板和 375px 均无横向滚动；键盘顺序与视觉顺序一致；动效尊重 reduced motion。

## 2. 目标

- 默认用配置概览回答“当前配置到哪一步、下一步做什么”。
- 把设置分成“概览、工作区、模型服务、运行诊断”四个清晰任务域。
- 一次只显示一个任务域的主要内容，消除完整卡片纵向堆叠。
- 让 Provider 创建、诊断详情等复杂区域按需展开。
- 保留现有功能、错误恢复、安全边界和测试覆盖。
- 保持桌面与 375px 移动端可访问、可键盘操作且无横向溢出。

## 3. 非目标

- 不新增或修改后端 API、数据库、Provider 协议和模型绑定格式。
- 不改变 Runtime graph、自检、安全审计或 HITL 状态转换。
- 不实现 R1.2 context compression、token/context 计量或 R2 功能。
- 不进行品牌重做、深色模式新增或全局组件库迁移。
- 不修改 `docs/my_idea.md`。

## 4. 信息架构

### 4.1 概览

设置页默认进入“配置概览”。概览由四个状态项组成：

1. **工作区**：未初始化、正在恢复或已就绪。
2. **Provider**：尚未添加、已有 Provider 或加载失败。
3. **模型用途绑定**：待配置、部分配置或四个角色均已绑定。
4. **运行诊断**：待运行、最近成功、需要处理或存在待人工确认动作。

每个状态项包含图标、标题、状态文字、简短说明和进入对应分组的按钮。未初始化 Workspace 时，概览只突出“初始化工作区”这一主操作；后续状态项显示为什么暂不可用。Workspace 就绪后，概览按配置顺序给出唯一“下一步”建议。

概览不复制完整表单，也不建立独立持久化状态。它只根据现有组件已经读取或可复用的查询结果生成摘要；无法可靠读取的诊断历史使用“进入诊断查看”，不虚构成功状态。

### 4.2 工作区

工作区分组只包含 Workspace 路径、Vault 状态和初始化/更新操作。未初始化时显示可编辑路径和一个主按钮；已初始化时先显示只读摘要，修改路径属于次级操作。错误靠近表单显示，并保留可执行建议。

### 4.3 模型服务

模型服务分组按依赖顺序排列：

1. Provider 列表与连接状态。
2. 按需展开的“添加 Provider”表单。
3. 模型用途绑定。

页面默认优先展示已有 Provider。创建表单初始收起，通过带 `aria-expanded` 的按钮展开；成功创建后收起并刷新列表。Provider 编辑、模型添加、连接测试、删除冲突和模型用途绑定行为保持现状。没有 Provider Model 时，绑定区解释前置步骤并提供回到 Provider 区域的清晰提示。

### 4.4 运行诊断

运行诊断分组包含 Runtime、自检、安全检查和人工确认四个子区域。默认展示紧凑摘要与三个显式展开按钮：

- Agent Runtime
- 工具安全
- 人工确认

同一时间允许用户展开需要查看的区域，不强制手风琴互斥。每个按钮使用 `aria-expanded` 和 `aria-controls`。存在 pending action 时，概览显示提醒；进入运行诊断后人工确认区域自动展开。无 pending action 时仍保留现有诊断入口，但详情默认收起。

## 5. 页面结构与组件边界

`SettingsPage` 保持 Workspace 恢复、初始化和 Provider revision 的所有权，并新增当前分组状态：

```ts
type SettingsSection = "overview" | "workspace" | "models" | "diagnostics";
```

新增以下小型前端边界：

- `SettingsNavigation`：渲染四个分组，负责可访问选择，不读取业务数据。
- `SettingsOverview`：接收整理后的状态项和导航回调，只负责摘要展示。
- `SettingsDisclosure`：统一诊断子区域的展开按钮、`aria-expanded` 和内容容器。

现有组件继续承担业务职责：

- `ProviderManager`：Provider 与 Provider Model 生命周期；新增受控或内部的创建表单展开状态。
- `ModelBindings`：四个模型用途绑定。
- `RuntimeDiagnostics`：Runtime session 与事件自检。
- `SecurityDiagnostics`：工具安全检查。
- `ActionCenter`：HITL 诊断与 pending action 决策。

组件之间不读取彼此内部 state。概览只使用 `SettingsPage` 已有 Workspace 状态和窄的 Provider/绑定摘要查询；详情组件继续使用现有 API。若复用查询会造成重复请求，应通过 TanStack Query 的稳定 query key 共享缓存，而不是把详情逻辑上移到大组件。

## 6. 响应式布局

### 6.1 桌面

1024px 以上使用两列：`220–240px` 设置导航和 `minmax(0, 1fr)` 内容区。导航可在内容滚动时保持可见，但不得覆盖页面标题。内容区限制最大阅读宽度，表单和状态列表不横跨整个屏幕。

### 6.2 平板与移动端

1024px 以下切换为单列。四个分组使用可换行的分段导航，不采用固定宽度横向滚动标签。375px 下每项至少 44px 高，标签不截断；内容顺序为分组标题、状态说明、主要操作、次级内容。长路径允许换行，Provider 操作按钮可换行但保持 DOM 与视觉顺序一致。

## 7. 视觉与交互规则

- 沿用现有浅色表面、语义色、圆角、阴影和 Lucide 线性图标。
- 不使用 emoji、图标字体或新的品牌色。
- 概览状态必须同时有文字和图标；颜色不是唯一信息来源。
- 选中导航使用背景、边框和文字权重共同表达，并设置 `aria-current="page"`。
- 所有按钮、导航项和 disclosure 触发器不小于 44px，具有 hover、pressed、focus-visible 和 disabled 状态。
- 每个分组只保留一个 primary button；其它动作使用 secondary/ghost 层级。
- 展开与切换只使用 150–200ms 的颜色、边框、透明度变化，不动画 width/height，不引发布局抖动。
- `prefers-reduced-motion: reduce` 时取消非必要过渡。

## 8. 状态与错误处理

- Workspace 恢复期间显示稳定占位，不渲染可误操作的模型和诊断详情。
- Workspace 恢复或初始化失败时，错误显示在工作区分组；概览对应项显示“需要处理”并可跳转。
- Provider 或绑定摘要失败时，概览显示“读取失败”，进入模型服务后使用现有错误与恢复路径。
- 切换分组不清空已填写但未提交的 Provider 表单；主动收起有修改的复杂表单时需要确认，若当前组件尚无 dirty 状态则不新增伪确认。
- pending action 不因切换分组丢失；人工确认解决后继续使用现有查询刷新和状态消息。

## 9. 测试与验收

### 9.1 针对性测试

- 默认显示配置概览，不同时渲染四个完整详情区域。
- 四个分组可通过键盘语义按钮切换，选中项具有 `aria-current`。
- Workspace 未初始化时概览主操作进入工作区；初始化后摘要与下一步更新。
- 模型服务按 Provider → 绑定顺序显示；添加 Provider 表单默认收起并可展开/收起。
- 运行诊断详情默认收起，触发器具有正确 `aria-expanded`；人工确认入口保留。
- 现有 Provider、模型绑定、Runtime、安全和 ActionCenter 行为测试继续通过。

### 9.2 浏览器验收

- 1440×1000：概览、左侧导航、单内容面板和主操作层级正确。
- 375×812：分段导航可换行、路径和按钮不溢出、无整页横向滚动。
- Tab 顺序与视觉顺序一致，Enter/Space 可切换分组和 disclosure。
- 页面刷新回到概览；Workspace、Provider 和绑定数据从服务端恢复。
- 浏览器控制台无 error/warning，reduced-motion 下没有依赖动画才能理解的状态。

### 9.3 回归预算

开发期间只运行设置页及受影响组件测试。最终运行一次前端全量回归、TypeScript/build 和完整浏览器验收。本切片没有后端改动，不重复执行后端全量回归。

## 10. 完成边界

本切片完成后，设置页达到“配置状态可理解、任务域可定位、复杂内容按需出现”的体验标准。它不代表 R1.2 context/token 基础能力完成，也不开始 R2。下一产品切片仍为 R1.2 context compression and token/context usage foundation。
