# Agent 会话工作台设计与开发准则

日期：2026-07-24

状态：Accepted

适用范围：题库整理、复习讨论、画像助手、后续求职目标与模拟面试等所有用户可见 Agent 会话。

## 1. 产品结构

所有 Agent 采用统一的两级结构：

```text
会话记录
  → 打开或新建会话
会话工作台
  ├─ 会话标题栏
  ├─ 对话主区
  └─ 上下文与运行侧栏
```

- 会话记录与会话工作台是两个界面状态，不在工作台左侧永久挤入会话列表。
- 会话工作台必须复用共享 Shell。Agent 只提供名称、快捷问题、上下文面板和业务产物卡片。
- 画像助手继续位于“个人画像”的一级页签下；页签保留，工作台消费页签以下的全部剩余高度。
- R2 题库整理会话是当前视觉与交互基准。本阶段不重写其业务行为；画像助手先对齐，R2 的薄包装迁移另行执行。

## 2. 桌面与响应式布局

- `≥ 1200px`：对话主区使用剩余宽度，右侧栏固定在 `300–340px`。
- `768–1199px`：默认展示对话，右侧内容通过“本次依据”按钮打开侧边面板。
- `< 768px`：右侧内容进入独立子页面或底部面板，不与消息区并排。
- 桌面右侧栏默认展开但允许收起。收起偏好按 Agent 类型保存在本地界面状态，不写入业务会话。
- 页面本身不得滚动；消息区与右侧栏分别拥有内部纵向滚动。
- 输入区固定在对话主区底部。禁止 Agent 页面自行计算 `calc(100dvh - Npx)`；高度由共享工作台连续传递，所有 Grid/Flex 中间层必须设置 `min-height: 0`。
- 状态、警告或待处理数量只能提示侧栏按钮，不得强制展开打断用户。

## 3. 会话标题栏

标题栏固定包含：

- 返回会话记录；
- 当前会话标题；
- 手动重命名；
- 最近一次 Execution 的用户化状态；
- 中屏和移动端的“本次依据”入口。

新会话以 placeholder 标题创建。首次成功运行后由共享 `SessionTitleMiddleware` 生成标题；生成失败时使用第一条用户消息的确定性安全截取。用户手动重命名后，`title_source` 必须切换为 `user`，中间件不得覆盖。

## 4. 会话记录与生命周期

- 默认按最近更新时间倒序。
- 支持标题和最近消息搜索。
- 主列表筛选为“全部 / 正在运行 / 需要处理”。持续对话不使用误导性的“已完成会话”。
- 会话生命周期只有“使用中 / 已归档”；运行状态属于 Execution。
- 默认操作是归档。归档进入回收站，可恢复；永久删除只在回收站中提供。
- 运行中的会话不得归档或永久删除，必须先停止。
- 返回列表后恢复此前的筛选和滚动位置。
- 不同会话允许并发；同一会话同一时刻只允许一个活跃 Execution。共享业务资源的并发由领域幂等、去重和乐观锁处理。

## 5. 消息与 Markdown

- 普通消息统一使用头像、角色名、北京时间、消息气泡和最大可读行宽。
- API 与数据库时间以 UTC 为权威；界面统一通过共享时间工具转换为 `Asia/Shanghai`。SQLite 无时区时间必须先按 UTC 解析，Agent 组件不得直接使用 `new Date(value)` 猜测时区。
- Agent 正文统一通过 `MarkdownView` 渲染；禁止把模型正文直接塞入 `<p>`。
- 用户消息、Agent 消息、流式消息、过程卡和失败卡使用共享组件与状态语义。
- 画像建议、评估结果等领域卡片通过消息插槽加入时间线，不得复制整套聊天布局。
- 消息流中的产物卡记录“当时生成了什么”；右侧栏维护“现在还有什么待处理”。两处必须进入同一个业务详情。
- 当前不提供任意历史节点改写、分叉或通用 Time Travel。未来分叉必须显式创建新会话。

消息操作：

- 用户消息：复制；最后一条失败请求可重新发送。
- Agent 消息：复制；查看本次依据；失败时重试。
- 历史消息不可原地编辑并覆盖后续记录。

## 6. 流式输出与滚动

- 首次进入会话定位到最后一条完整消息。
- 用户发送后滚到底部。
- 用户位于底部附近时，流式内容自动跟随。
- 用户主动上滚后禁止强制拉回，显示“有新回复，回到底部”。
- 会话分别保存滚动位置；切换会话、侧栏开关、输入框聚焦和窗口缩放不得错误重置。
- Tool 阶段更新与领域卡异步加载不能引起页面级跳动。

## 7. 过程卡、状态与恢复

一次 Execution 在消息流中最多产生一张过程卡：

- 运行中默认展开，展示用户能理解的阶段；
- 完成后默认折叠，只保留耗时、读取数量和完成状态；
- 失败或停止时保持展开，展示重试、继续或调整范围；
- Tool 名、Event 类型、调用 ID 和数据库字段不得进入用户文案；
- 原始 Trace、模型、Token 和调用次数只放在右侧技术详情；
- 最终回答必须作为独立消息存在。
- 运行中耗时由持久化 `startedAt` 配合前端本地秒表实时计算，不需要每秒请求后端；终态使用 `finishedAt` 冻结，刷新后必须恢复为相同结果。

恢复语义：

- 停止终止当前 Execution，但保留会话、消息和已持久化产物。
- 重试创建新 Execution，并记录原 Execution 关联；原失败记录保留。
- 只有存在稳定 checkpoint 的长任务才显示“继续处理”；否则使用“重新尝试”。
- 刷新后必须从持久状态恢复失败、停止和对应操作，不得继续显示幽灵转圈。

## 8. 输入区与 Execution 配置

- 所有 Agent 使用共享固定底部输入区。
- 文本框默认一行，自动增长范围为 `44–128px`。
- `Enter` 发送，`Shift+Enter` 换行，输入法组合期间不得误发送。
- 快捷问题只填充输入框，不直接调用模型。
- 模型和思考强度显示在左下角；发送/停止位于右侧固定位置。
- 配置层级为“Agent 用途默认 → 会话默认 → Execution 不可变快照”。
- 新会话读取用途绑定；会话记住最近一次选择；每次发送持久化快照。
- 模型失效时要求用户重新选择，不得静默换模型后调用。

## 9. 画像助手右侧栏

画像助手右侧栏按以下顺序组织：

1. 本次参考资料：类别、条数与可调整范围；
2. 使用边界：仅已确认画像，不读取待确认建议和原始敏感内容；
3. 待处理产物：画像建议、评估或 Action Plan；
4. 运行状态：阶段、耗时、停止/重试；
5. 技术详情：模型、调用次数、Token 和上下文整理状态，默认折叠。

参考范围是会话默认值；每次发送把当时范围写入 Execution 输入。修改范围只影响后续请求，历史回答继续对应原快照。

## 10. 状态所有权

```text
Session   → 身份、标题、生命周期、会话默认值
Execution → 运行状态、配置快照、取消与恢复
Message   → 已持久化对话内容
Event     → 实时过程与增量
Artifact/Proposal → 需要后续处理的领域产物
```

- SSE 只负责实时体验，不能替代持久状态。
- SSE 与持久状态冲突时，终态的持久 Execution 优先。
- 停止、重试与继续必须绑定明确的 `execution_id`。
- 前端状态按 `session_id + execution_id` 归并；禁止使用页面级全局 `busy` 代表所有会话。

## 11. 强制验收门禁

固定验证 `390 / 768 / 1024 / 1200 / 1440`：

- 页面级高度不超过可用视口；
- 页面无横向溢出；
- 消息区和右侧栏滚动互不影响；
- 输入区始终可达；
- 空会话、长 Markdown、运行中、停止、失败、重试、领域产物和长会话列表均成立；
- 用户上滚后流式输出不抢位置；
- 模型配置、参考范围和历史 Execution 快照一致；
- 标题自动生成、手动重命名、归档、恢复和永久删除成立；
- 键盘可完成会话进入、发送、打开侧栏、重命名和恢复操作。

新增 Agent 的代码评审必须回答：

1. 复用了哪些共享 Agent 组件？
2. 谁拥有页面、消息区和侧栏的滚动？
3. 哪些状态来自 Session，哪些来自 Execution？
4. 是否存在 Agent 专属布局或消息 CSS；若存在，为什么共享插槽不够？
5. 刷新后能否仅靠持久状态恢复当前页面？
