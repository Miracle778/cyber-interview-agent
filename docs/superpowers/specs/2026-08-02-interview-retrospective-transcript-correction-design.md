## 1. 背景

手机录音转写常包含同音字、错别字、错误断句、技术名词误识别、重复词和不完整语句。如果问题识别与逐题分析直接读取这些文字，错误会继续传播到问题还原、回答评价、题库候选和项目经验候选。

现有 Cleanup 阶段已经拥有长文本窗口、说话人识别、段落整理、停止恢复、超时拆分和用户确认，但它没有把“原文”和“修订后文字”作为可审计的两个层次表达，也没有要求高风险语义修改先由用户确认。

本增量将文字修订纳入现有转写整理版本。它不增加第二套长文档任务，不把原文替换成模型改写稿，也不允许模型为了语言通顺补写缺失事实。

## 2. 产品目标与非目标

目标：

- 在复盘分析前修正可确定的转写错误；
- 永久区分不可变原文、模型建议、用户决定和最终分析文字；
- 让低风险修订尽量自动完成，高风险修订必须显式确认；
- 继续支持一小时以上转写的渐进保存、停止、刷新、恢复和局部重试；
- 分析、引用和导出默认使用确认后的修订文字，同时保留回看原文的能力；
- 改善整理中的进度反馈，不让首个窗口返回前的页面表现为长时间静止；
- 修复运行中心结构化模型响应中对象数组被渲染为巨大胶囊的问题。

非目标：

- 不做事实核验、答案纠正或技术结论润色；
- 不补写录音中缺失的面试官提问、候选人回答或上下文；
- 不引入通用文档校对平台、全局术语库或联网搜索；
- 不把题库答案、画像评价或历史复盘结论作为修订依据；
- 不用模型内部百分比或 Token 流伪造转写整理进度。

## 3. 权威证据链

```text
SourceVersion：不可变原文
  ↓ 长文本 Cleanup Agent
CleanupVersion
  ├─ SegmentRecord：说话人、原文位置、当前采用文字
  └─ CorrectionRecord：原文、建议、风险、原因和用户决定
  ↓ 用户确认
AnalysisRun：只读取确认后的 SegmentRecord
```

规则：

- `SourceVersion.body` 在清除前始终保存用户提交的原始文字；
- `SegmentRecord.body` 是该 CleanupVersion 当前采用的修订文字；
- `SegmentRecord.source_start/source_end` 继续指向不可变原文范围；
- `CorrectionRecord` 解释原文如何变成当前采用文字；
- review_pending 的 CleanupVersion 可以通过现有 optimistic version 修改；确认后不可变；
- 修改已确认版本时创建新的 CleanupVersion，不能原地覆盖历史；
- AnalysisRun 只能引用 `confirmed` CleanupVersion。

## 4. 修订类型与风险分级

### 4.1 格式整理

包括标点、空格、重复换行和不改变含义的断句。默认自动接受，不逐项展开。相邻格式变更可以合并为一条记录，避免制造大量无价值审阅项。

### 4.2 明显识别错误

包括错别字、同音词、重复词和上下文唯一确定的技术名词。默认自动接受，但在段落上显示弱提示，用户可以展开、撤销或手动修改。

技术名词只有在以下条件同时满足时可以作为低风险自动修订：

- 修订结果来自本次允许的上下文词汇；
- 原词与目标词符合明显的 ASR 音近、形近或拆词错误；
- 修改不改变技术结论、主体、数量或否定关系。

### 4.3 可能影响语义的修改

以下修改必须升级为高风险并等待用户决定：

- 否定词、数量、时间、比例、版本和范围；
- 主语、说话对象、公司名、项目名或无法由允许上下文唯一确定的专有名词；
- 技术因果、方案取舍、故障结果或能力结论；
- 多种修订都合理的歧义内容；
- 不完整语句、录音缺失或无法可靠理解的内容。

模型无法确定时必须保留原文并标记原因，不能输出自认为合理的完整句。对于没有可靠建议的不完整内容，页面只提供“保留原文”和“手动修改”，不能伪装成已完成的自动修正。

### 4.4 用户决定

高风险修订的决定为：

- `accepted`：接受模型建议；
- `kept_original`：保留原文；
- `manual`：采用用户手动文字。

低风险修订初始为 `auto_accepted`，用户撤销后变为 `kept_original`，用户编辑后变为 `manual`。用户决定优先级高于模型建议。

## 5. 允许的上下文

Cleanup Agent 只能读取：

- 当前窗口及其有界重叠前后文；
- 首个成功窗口冻结的说话人提示；
- 当前求职目标的公司、岗位和 JD 技术词；
- 用户已有项目名称及明确登记的技术栈名称；
- 源版本冻结的录音覆盖范围。

它不能读取：

- 题库参考答案和掌握度；
- 画像评价、能力结论或模型推断；
- 历史复盘的改进答案；
- Knowledge 总结或外部网页。

上下文只帮助识别词汇，不能作为补写当前录音事实的证据。

## 6. 长文本执行与输出契约

继续复用现有自然边界窗口、重叠上下文、最多并发 2、120 秒 Provider 超时、两次应用尝试和超时窗口拆分。

每个窗口同时输出：

- 有序段落、说话人和绝对原文 offset；
- 每个段落当前建议采用的文字；
- 该窗口产生的连续修订记录；
- 无法安全修订的高风险不确定项。

每条修订至少包含：

- `sourceStart/sourceEnd`；
- `originalText`；
- `suggestedText`，无法安全建议时为空；
- `changeType`：`formatting / recognition / semantic`；
- `riskLevel`：`low / high`；
- `reason` 和 `confidence`。

重叠区只提供上下文，`emitFrom` 之前不得输出段落或修订记录。Reducer 按绝对 offset 单线程合并段落和修改；同一原文范围的冲突输出不能静默择一。

## 7. 确定性校验

窗口输出落盘前必须验证：

- 修订范围位于当前窗口允许输出范围；
- `originalText` 与 SourceVersion 对应范围完全一致；
- 建议文字不得为空，除非该记录明确表示无法安全修订的不完整内容；
- 修订范围有序且互不冲突；
- 模型不能把确定性规则识别出的高风险字段降级为低风险；
- 修订不能新增原文中不存在的完整对话轮次；
- 段落 offset、修订 offset 和最终采用文字可以一致重建。

校验失败只使当前窗口重试，不删除其他窗口的已完成结果。

## 8. 整理确认页面

### 8.1 处理中

页面展示确定性的窗口完成进度和非确定性的活动状态：

- `已完成 N / M 个文本窗口`；
- 活动窗口数量；
- 当前活动持续时间与最近保存时间；
- 已完成比例进度条；活动中的部分只显示流动动画，不计算虚假百分比；
- 首个窗口完成后立即展示已保存段落和修订预览；
- 等待超过 60 秒时说明长转写首批可能较慢且可以离开页面；
- 达到 Provider 超时边界后进入明确的拆分、重试或失败反馈。

API 投影补充 `activeSince` 与 `latestProgressAt`，刷新后继续使用服务端工作项时间，不从零重新计时。

### 8.2 整理完成

顶部摘要显示：

- 自动修正数量；
- 待确认高风险数量；
- 说话人待确认段落数。

左侧仍按时间展示段落。低风险修改显示弱“已修订”标签，高风险修改显示“需要确认”。右侧默认展示修订稿，并提供“修订稿 / 对照原文”切换。对照模式使用行内差异，不增加双栏全文编辑器。

高风险修订在当前段落内逐项处理。普通格式和明显错字不会阻止确认；未处理高风险项、未确认说话人或没有可用段落时，“确认整理结果”不可用。

## 9. 分析、引用、导出与原文清除

- 问题提取、逐题分析和候选生成只读取确认后的 `SegmentRecord.body`；
- 页面引用默认显示修订文字，有修改的段落显示“已修订”；
- 点击“已修订”可以查看原文、建议、原因和用户决定；
- 导出复盘默认使用修订稿，诊断包在原文仍可用时包含修改映射；
- 清除原文时必须同时删除 CorrectionRecord 中复制的原文和建议正文，以及可重读 Trace 正文；
- 清除后保留修改类型、风险、决定、哈希和结构化结论，但不再声称可以查看原文差异。

## 10. 失败与恢复

- 每个窗口独立持久化，已完成窗口在停止、刷新、进程重启和重试后继续保留；
- 只领取 pending、retryable 或 interrupted 工作项；
- 超时大窗口继续原子替换为更小的重叠子窗口；
- 用户编辑使用 expected version，冲突时提示刷新，不静默覆盖；
- 某窗口最终失败时可以查看已保存段落，但不能确认不完整 CleanupVersion；
- 未解决高风险修订时不能创建 AnalysisRun。

## 11. 运行中心结构化响应展示修复

运行中心的模型响应只表示 Provider 成功返回，不表示内容正确，因此：

- 结构化结果容器使用中性 surface 和普通边框；
- 绿色只用于小型“模型已返回”状态或左侧细色条；
- 简单字符串、数字数组可以继续显示为紧凑标签；
- 对象数组必须显示为普通矩形结果卡，不能继承 `border-radius: 999px` 的胶囊样式；
- 嵌套对象继续使用字段列表，并保持长文本可换行、可滚动；
- 该修复不改变 Trace 正文、格式化 JSON 或原文 JSON。

## 12. 验收

自动测试覆盖：

- 格式、错字、同音词和允许技术名词的低风险修订；
- 否定词、数字、时间、主体和技术结论的高风险升级；
- 不完整语句保留原文并等待确认；
- 原文范围不匹配、越界、重叠冲突和空建议拒绝；
- 窗口重叠不重复生成段落或修订；
- 超时拆分、停止、刷新和恢复不丢失修订；
- 接受、保留原文和手动修改形成正确最终正文；
- 未处理高风险项不能确认或开始分析；
- 分析、引用和导出使用确认后的修订稿；
- 原文清除同步移除修订正文副本；
- 活动时间和最近进度刷新后保持；
- 对象数组使用普通卡片，简单值数组使用紧凑标签。

浏览器验收使用不含个人信息的合成长转写，覆盖桌面和 390px。合成文本必须包含技术名词、ASR 同音错误、否定词、数字和不完整语句。真实 Provider 与真实长转写只在用户明确授权后执行，重点记录误改率、高风险召回和用户撤销情况，而不只记录任务是否完成。

## 13. 交付拆分

后续实施计划按纵向任务拆分：

1. CorrectionRecord 迁移、领域模型、API 与原文清除边界；
2. Cleanup Agent 合同、Prompt、窗口校验和 Reducer；
3. 修订决定、确认门禁、分析输入与版本冲突；
4. 整理进度、修订对照和移动端交互；
5. 运行中心结构化响应样式修复；
6. 回归、隔离浏览器验收和文档门禁。
