## 1. 问题与产品目标

个人画像已经能保存用户确认过的工作经历、项目、技能和成果，但用户仍需要把这些长期资料转化为一次具体面试的准备结果。

本阶段提供一条完整的纵向流程：

```text
创建求职目标
→ 明确岗位方向或粘贴 JD
→ 提取并确认岗位要求
→ 关联已确认画像和项目
→ 选择重点项目
→ 进行项目深挖
→ 沉淀项目讲解与差距
→ 生成项目经历题
→ 进入复习并更新准备状态
```

产品承诺是：

> 针对用户想去的岗位，基于其真实做过的项目，帮助用户把经历讲清楚、讲具体，并提前发现经不起追问的部分。

本阶段不把个人画像、聊天次数或模型评分包装成价值。价值来自可追溯的岗位要求、可复用的项目讲解、明确的准备风险和可练习的问题。

## 2. 目标用户与适用边界

首版面向：

- 有真实工作或项目经历的软件工程师；
- 正在准备一个明确岗位方向或具体 JD；
- 多个岗位通常复用同一组核心项目；
- 希望复习本人项目问题，而不只复习通用技术题。

首版不专门覆盖：

- 尚无任何真实项目经历的应届或转行用户；
- 招聘团队、多人协作或企业权限；
- 自动求职、自动投递和申请进度管理。

## 3. 核心领域对象与所有权

### 3.1 求职目标

一个求职目标对应一个具体准备目标，例如“某公司高级后端工程师”或“高级 Python 后端方向”。

求职目标拥有：

- 公司、岗位、职级、来源链接等元数据；
- 一个当前 JD 版本，或一个岗位方向参考版本；
- 已确认岗位要求；
- 要求与画像、项目、讲解内容之间的关联；
- 核心项目和补充项目优先级；
- 当前目标下的专项问题、风险和准备状态；
- 该目标下的岗位分析任务和项目深挖会话。

求职目标不拥有：

- 简历文件或原文；
- 统一画像事实；
- 全局项目实体；
- 通用项目讲解事实；
- 已确认进入题库的项目经历题。

### 3.2 统一画像与项目集合

同一 Workspace 继续只有一份统一画像。项目是统一画像中的全局长期资产，不在每个求职目标内重复创建或复制。

不同目标可以：

- 对同一个项目给出不同相关性排序；
- 选择不同的重点项目；
- 保存不同的岗位专项问题和风险。

删除求职目标不会删除统一画像、全局项目、通用项目讲解或已进入题库的问题。

### 3.3 通用项目讲解与目标专项成果

项目深挖的产物分成两层：

| 层级 | 所有者 | 示例 |
|---|---|---|
| 通用项目讲解 | 统一画像中的项目 | 背景、本人职责、方案选择、难点、结果、取舍和复盘 |
| 目标专项成果 | 求职目标 | 与当前 JD 的关联、专项追问、风险、项目优先级和准备状态 |

界面可以把两层内容组合成一张“项目讲解”视图，但保存和删除边界必须分离。

## 4. 首版范围

必须交付：

1. 求职目标创建、编辑元数据、归档、恢复和回收站永久删除；
2. 粘贴纯文本 JD，或根据岗位方向与职级生成参考要求；
3. JD 不可变版本、差异分析和当前版本确认；
4. 岗位要求提取、逐条编辑、拆分、合并、删除和批量确认；
5. 岗位要求与已确认画像、全局项目和通用讲解的候选映射；
6. 一个核心项目和最多两个补充项目的选择；
7. 可暂停、终止、恢复的项目深挖 Agent；
8. 增量项目讲解草稿、分节确认和四类差距；
9. 项目经历题候选、确认入库、题库分类和最小训练闭环；
10. 长任务进度、耗时、Token、上下文、隐私范围和失败恢复；
11. 准备状态和完成条件。

明确不做：

- 招聘网站抓取、登录态读取和 URL 自动解析；
- 截图、OCR、PDF 或 Word JD 解析；
- 自动生成、修改或投递简历；
- 求职申请进度和正式 Todo Service；
- 完整技术面、HR 面模拟；
- 真实面试复盘；
- 多用户协作；
- Agent 自动修改画像、讲解或正式题库；
- 通用 Time Travel、自由 ReAct 写入或无限 Planner。

## 5. 求职目标生命周期

### 5.1 创建

最少需要：

- 岗位名称；
- 职级或经验范围；
- 公司名称可选；
- 来源链接可选；
- JD 正文可选。

没有 JD 时，用户可以直接创建岗位方向目标。

### 5.2 活跃与归档

生命周期只有：

- 使用中；
- 已归档；
- 回收站。

准备进度不是生命周期。用户手动归档目标；系统不因准备完成而自动归档。

### 5.3 永久删除

永久删除只在回收站中提供，提交前展示影响范围。

删除：

- 目标元数据；
- JD 与岗位方向参考版本；
- 岗位要求和确认记录；
- 画像与项目映射；
- 目标项目优先级；
- 目标下的深挖会话、风险和准备状态。

保留：

- 统一画像和简历来源；
- 全局项目；
- 已确认通用项目讲解；
- 已确认进入题库的项目经历题；
- 既有复习记录。

运行中的岗位分析或深挖 Execution 会阻止归档和永久删除。未确认建议由用户选择保留为独立草稿或随目标删除。

## 6. JD 与岗位方向参考

### 6.1 首版输入

支持：

- 粘贴纯文本 JD；
- 手动填写公司、岗位、职级和来源链接；
- 无 JD 时根据岗位方向和职级生成参考要求。

岗位方向生成内容必须持续标记为“岗位方向参考”，不能伪装成公司官方要求。

### 6.2 不可变版本

JD 正文不可原地覆盖：

```text
编辑或重新粘贴正文
→ 创建新版本
→ 提取新增、修改和删除要求
→ 用户确认差异
→ 设为当前版本
```

公司、岗位、职级和来源链接等元数据编辑不创建 JD 版本。

旧版本的岗位分析、项目映射和训练记录继续保留。切换当前版本不会静默覆盖旧结论。

### 6.3 岗位分析任务

岗位分析是可恢复后台任务，不是长期对话。

可见阶段：

1. 读取岗位内容；
2. 整理岗位要求；
3. 关联个人资料；
4. 分析项目相关性；
5. 等待用户确认。

同一目标同一时刻只允许一个岗位分析任务运行。

## 7. 岗位要求

### 7.1 原子要求

每条要求必须能被单独核对，包含：

- 类型：职责、技能、经验、项目；
- 优先级：必须项、加分项；
- 来源：JD 原文位置或岗位方向参考；
- 正文；
- 确认状态；
- 当前个人准备状态。

模型推断的隐含要求与原文提取内容分开展示，并明确标记为建议。

### 7.2 用户确认

用户可以：

- 编辑；
- 拆分；
- 合并；
- 删除；
- 逐条确认；
- 勾选批量确认；
- 确认当前筛选范围内全部未修改、无冲突的原文提取项。

推断项、冲突项、缺少稳定来源的条目不能被一键静默确认。

只有已确认要求可以参与项目排序、风险判断和准备完成状态。未确认内容只作为建议存在。

### 7.3 个人准备状态

每条已确认要求使用四种状态：

- 已有可靠证据；
- 待深入验证；
- 资料待补充；
- 暂无相关经历。

不展示单一匹配百分比。

状态依据必须可定位到：

- 已确认 Profile ClaimVersion；
- 全局项目；
- 已确认通用项目讲解；
- 项目训练结果；
- 明确的未知或缺失记录。

Agent 自动生成的关联只能进入“候选关联”。经用户确认或训练验证后，才能升级为“已有可靠证据”。

## 8. 画像版本与重新分析

每次岗位分析保存：

- `profileVersion`；
- 使用过的 ClaimVersion ID；
- 项目与通用讲解版本引用；
- JD 版本；
- 模型和上下文范围快照。

统一画像发生变化后：

- 旧分析标记为“个人资料已更新，建议重新分析”；
- 重新分析只生成关联和状态差异；
- 不静默覆盖用户确认过的映射；
- 旧分析历史继续可查看。

目标读取统一画像，不绑定某一份简历。原始简历只有在用户主动查看依据时进入私有阅读器，默认不发送给岗位 Agent。

## 9. 项目相关性与选择

Agent 对全部已确认项目给出：

- 相关要求；
- 支持证据；
- 仍需核对的部分；
- 选择理由和风险。

项目数量不设数据层硬上限，但首版准备主流程采用：

- 一个核心项目；
- 零到两个补充项目；
- 其他项目只保留相关性分析。

Agent 提供排序建议，最终由用户选择。核心项目负责主要面试叙事，补充项目只覆盖核心项目无法证明的关键要求。

正式深挖只能从已确认的全局项目启动。缺少项目时，先回到个人画像补充并确认。

## 10. 项目深挖 Agent

### 10.1 会话身份

一个 `(求职目标, 项目)` 默认只有一个主要深挖会话，可跨天暂停和恢复。

相同项目在不同求职目标下拥有不同的目标专项会话，但共享已确认的通用项目讲解。

用户可以结束当前轮并新建下一轮；旧轮归档保留。不提供会话分叉和 Time Travel。

### 10.2 有界阶段

深挖采用可见、有边界的 Plan-and-Execute：

1. 项目背景与目标；
2. 本人角色与职责；
3. 关键方案及选择理由；
4. 最难问题与解决过程；
5. 结果与可量化影响；
6. 取舍、失败与复盘；
7. 当前岗位专项追问。

每次只提出一个核心问题。模型可以根据回答生成有限追问，但不能自由扩展成无限计划。

用户可以：

- 跳过当前问题；
- 暂停本轮；
- 终止本轮；
- 从检查点恢复；
- 基于当前成果提前结束并整理。

### 10.3 一次回答的模型调用

正常情况下，每次用户回答只触发一次主要结构化模型调用，同时返回：

- 本轮回答评价；
- 通用讲解草稿增量；
- 目标专项结论；
- 差距建议；
- 下一个问题。

标题、分类、总结和题目生成不能在每轮额外串行调用模型。

结构化输出无法解析时最多进行一次修复调用。修复仍失败则保留用户回答，进入可重试状态，不循环重试。

## 11. 项目讲解草稿与确认

每完成一个阶段，系统保存可见但未确认的增量草稿。刷新、暂停或模型失败后，已经保存的阶段成果仍然存在。

用户可以：

- 查看当前通用讲解草稿；
- 查看目标专项内容；
- 按章节编辑和确认；
- 确认安全的多个章节；
- 在中途选择“整理本轮成果”。

正式确认采用章节级 Diff：

```text
当前已确认内容
→ 本轮建议内容
→ 增删改差异
→ 用户确认
→ 确定性领域服务写入新版本
```

部分完成的章节可以先确认，不要求整张讲解一次完成。

## 12. 四类差距

深挖中发现的问题统一形成“待处理建议”：

| 类型 | 用户表达 | 去向 |
|---|---|---|
| 资料缺口 | 个人资料还不完整 | 创建待确认画像补充 |
| 表达缺口 | 经历真实，但暂时讲不清 | 继续深挖或修改项目讲解草稿 |
| 知识缺口 | 原理或技术细节掌握不足 | 创建项目经历题候选 |
| 经历缺口 | 确实没有相关经历 | 记录为求职目标风险 |

差距分类由 Agent 建议。画像、项目讲解和题库的正式写入继续由用户确认。

经历缺口不能被模型改写成虚构项目事实。

## 13. 项目经历题

### 13.1 正式题型

题库新增正式类型“项目经历题”，不使用普通 topic 标签冒充题型。

组织方式：

```text
项目经历题
→ 具体项目
→ 能力维度
→ 题目
```

首版能力维度：

- 背景与职责；
- 架构与方案；
- 难点与问题解决；
- 结果；
- 取舍、失败与复盘；
- 岗位专项。

项目题属于用户和全局项目。来源可以记录求职目标或未来面试复盘，但删除来源目标不会删除已确认题目。

### 13.2 候选生成

完成一轮项目深挖后，使用一次有界批量调用生成候选题。

暂停或提前结束时，用户可以手动选择“基于当前成果生成题目”，页面明确提示素材可能不完整。

候选题：

- 与同一项目的已有题目去重；
- 重复内容优先关联已有题或生成修订建议；
- 先保存在当前深挖成果中；
- 支持逐条编辑、忽略、确认和安全批量确认；
- 未确认前不进入正式题库。

### 13.3 最小训练闭环

项目经历题支持：

```text
候选
→ 确认入库
→ 从求职目标或题库开始练习
→ 用户回答
→ 基于已确认项目与讲解评价
→ 补充点和追问
→ 更新项目题掌握状态
```

评价维度：

- 事实一致；
- 细节具体；
- 结构完整；
- 经得住追问。

综合状态：

- 待补充；
- 基本可讲；
- 表达稳定。

不使用百分比。回答与已确认事实冲突时，用户选择：

- 我刚才说错了；
- 新说法准确，创建资料补充建议；
- 两种说法适用于不同场景，补充上下文。

冲突未解决时，该题不能进入“表达稳定”，但不会阻止整轮训练。

## 14. Message、Execution 与重试

用户消息和模型执行必须解耦：

```text
用户消息 M1 持久化一次
→ Execution E1 处理 M1
→ E1 失败或停止
→ M1 显示“本次处理未完成”
→ 重试创建 E2
→ E2.retryOfExecutionId = E1
→ E2.inputMessageId = M1
```

重试不能再创建一条相同用户消息。模型上下文只包含一次 M1。

修改后重试：

```text
创建 M2
→ M2.replacesMessageId = M1
→ M1 标记“已替换”
→ 活跃上下文排除 M1
→ 新 Execution 处理 M2
```

失败或停止产生的模型半成品、过程文本和 Tool 输出保留为审计事实，但不进入正式对话上下文、项目讲解或题库。

存在未解决的失败消息时，普通发送被阻止，用户必须选择：

- 按原内容重试；
- 修改后重试；
- 放弃本条并继续。

## 15. 状态、上下文与 Tool

### 15.1 最小 Agent State

项目深挖 Graph 显式使用最小 `state_schema`，只保存：

- 当前阶段；
- 当前问题和已完成阶段；
- 稳定追问 ID；
- 求职目标、项目、Session 和 Execution 引用；
- 暂停、结束和等待输入标记。

JD 正文、画像、项目讲解、Evidence、消息全文和产物正文不进入 Graph State。

### 15.2 Context Offload

领域资料保存在各自存储中，Agent 每个阶段按稳定引用重新组装最小上下文：

- 当前 JD 或岗位方向要求；
- 当前项目；
- 相关已确认画像字段；
- 已确认通用项目讲解；
- 最近对话或压缩摘要；
- 当前未解决问题。

对话压缩必须保留：

- 用户明确陈述的项目事实；
- 待处理和未解决内容；
- 当前阶段；
- 来源消息 ID。

原始消息继续持久化，摘要不是唯一事实来源。

### 15.3 Tool 权限

岗位分析和项目深挖只允许使用角色级最小只读 Tool：

- 读取当前求职目标与已确认要求；
- 读取有界的已确认画像；
- 读取当前项目、Evidence 引用和已确认通用讲解；
- 读取目标专项状态；
- 读取同一项目已有题目用于去重。

禁止模型直接：

- 修改或删除岗位要求；
- 修改画像；
- 修改通用项目讲解；
- 发布题目；
- 创建正式待办；
- 执行任意文件、数据库或外部操作。

所有写入都经过结构化建议、确定性服务、乐观锁、幂等键、用户确认和 Receipt。

## 16. 上下文与隐私展示

每次 Execution 展示“本次参考范围”：

- 当前 JD 或岗位方向要求；
- 当前项目；
- 相关已确认画像类别；
- 已确认项目讲解；
- 最近对话或上下文摘要。

默认排除：

- 原始完整简历；
- 联系方式和敏感字段；
- 无关项目；
- 其他求职目标的专项内容；
- 待确认、已拒绝或已替换的资料与消息。

首次使用外部 Provider 时明确说明将发送的资料类型。以后不重复弹窗，但右侧栏持续显示参考范围、模型、Token、上下文用量和整理状态。

## 17. 长任务、恢复与可观察性

岗位分析、项目匹配和题目生成超过一秒时展示真实阶段；超过十秒时同时展示：

- 本次实时耗时；
- 累计耗时；
- 已完成数量和总数量；
- 最近一次进展时间；
- 已保存成果；
- 失败后从哪里继续。

支持：

- 暂停；
- 终止；
- 从检查点恢复；
- 失败项重试；
- 刷新和重启后恢复真实状态。

已完成工作单元不会在恢复时重新执行。同一目标同类任务同一时刻只允许一个活跃 Execution。

页面不能用无事实支撑的百分比，也不能只显示无限转圈。

## 18. 信息架构与页面规则

新增一级入口“求职目标”，后续作为面试准备的主要工作台入口。

目标详情包含：

- 目标概览；
- 岗位要求；
- 项目深挖；
- 复习任务。

### 18.1 目标列表

展示使用中和已归档目标、当前准备状态、核心项目、风险和最近活动。创建入口不与历史列表争夺主空间。

### 18.2 目标工作台

这是工作台页：

- 页面本身不纵向滚动；
- 一级标题和子页签固定；
- 当前页签内容拥有明确滚动区；
- 长任务状态在目标工作区持续可见；
- 390、768、1024、1200、1440 下主操作始终可达。

### 18.3 项目深挖工作台

复用统一 Agent 会话工作台：

- 会话记录和会话工作台分离；
- 消息为主区；
- 当前阶段、参考范围、项目讲解草稿、待处理建议和技术详情进入右侧栏；
- 中屏使用侧边面板，移动端使用独立子页或底部面板；
- 页面不自算 `100dvh - Npx`；
- 输入法组合期间 Enter 不发送；
- 消息时间统一显示北京时间；
- 运行中耗时实时增长，终态冻结；
- Token、上下文与压缩状态可查看。

页面文案使用用户语言，不展示 Claim、Evidence、Tool、Event、snake_case 或数据库状态名。

## 19. 准备状态与完成条件

求职目标的派生状态：

- 待确认岗位要求；
- 待选择核心项目；
- 项目深挖进行中；
- 有高风险问题待处理；
- 核心准备已完成。

“核心准备已完成”必须同时满足：

1. 岗位要求已确认；
2. 已选择核心项目；
3. 核心项目通用讲解已完成并确认；
4. 所有必须项已有可靠证据，或被明确记录为已接受风险；
5. 当前目标的高风险项目题至少完成一次训练。

完成后继续展示已接受风险和可选优化项，不宣称用户已完全准备好。

## 20. 模型角色与调用预算

新增两个明确用途：

- `job_analysis`：岗位要求提取、画像与项目候选映射；
- `project_deep_dive`：项目深挖、回答评价和讲解增量。

历史 Workspace 首次迁移时分别以现有 `profile_assessment` 和 `agent_chat` 绑定作为默认值，之后用户可以独立配置。

项目题训练继续使用现有回答评价用途，但使用项目题专用 Prompt 与结构化评价契约。

预算原则：

- 岗位提取一次有界执行；
- 项目映射按项目批量、可恢复；
- 每次深挖回答一次主要调用；
- 候选题在阶段结束后一次批量调用；
- 会话标题只异步生成一次，失败时使用确定性截断；
- 格式修复最多一次；
- 不为每轮回答额外调用分类器、总结器或标题模型。

## 21. 验收标准

### 21.1 产品闭环

1. 用户可以用岗位方向或纯文本 JD 创建求职目标；
2. 岗位方向内容持续标记为参考，不伪装成官方 JD；
3. 用户可以确认原子岗位要求，并定位到原文来源；
4. 每项准备状态都能解释到画像、项目、讲解或明确缺失；
5. 用户可以选择一个核心项目和最多两个补充项目；
6. 用户可以完成、暂停、刷新、重启并恢复项目深挖；
7. 深挖形成可确认的通用讲解、目标专项结论和四类差距；
8. 项目经历题可以确认入库，并完成一次项目题训练；
9. 删除求职目标不会删除全局画像、项目、讲解或正式题目；
10. 画像变化会标记旧分析过期，并以差异方式重新分析。

### 21.2 运行与恢复

1. 同一用户消息重试不会生成重复消息；
2. 失败和停止输出不进入正式上下文；
3. 页面刷新后不出现幽灵运行状态；
4. 长任务显示阶段、耗时、数量、最近进展和恢复动作；
5. 已完成工作单元在恢复时不会从头重跑；
6. 同一目标同类任务不会并发覆盖；
7. Event、JSONL 和 API 时间以 UTC 保存，页面统一按 Asia/Shanghai 显示。

### 21.3 安全与隐私

1. 普通岗位分析和深挖不读取原始完整简历；
2. pending、rejected、superseded 和 replaced 内容不进入模型上下文；
3. Tool 的 Workspace、目标、项目和 Session scope 由服务端注入；
4. Agent 没有直接写画像、讲解或题库的工具；
5. 用户能看到每次 Execution 的参考范围、模型和 Token；
6. 首次外部模型调用前完成资料范围提示。

### 21.4 页面

1. 目标工作台和深挖工作台遵循现有页面与 Agent 准则；
2. 390、768、1024、1200、1440 无页面级横向溢出；
3. 工作台页面不超出可用视口，滚动区所有权清晰；
4. 输入区和主操作不需要滚动整个页面才能触达；
5. 长 JD、长项目讲解、空状态、运行中、失败和批量确认均不破坏布局；
6. 键盘可完成创建目标、确认要求、进入深挖、发送、停止、重试和打开参考范围。

## 22. 成熟度边界

本阶段完成后，产品具备“可信个人资料 → 岗位要求 → 项目深挖 → 项目题训练”的首条个性化准备闭环。

它仍然是单用户、本地优先、SQLite 持久化、单进程可恢复的工作台，不是分布式任务平台、招聘网站聚合器、自动求职系统或完整模拟面试产品。
