# Cyber Interview Agent MVP 产品设计文档

## 1. 产品定位

Cyber Interview Agent 是一个面试准备工作台。MVP 第一版聚焦一个完整闭环：

> 导入零散面试资料 -> 生成结构化题库 -> 通过 agent 对话练习 -> 生成掌握度报告 -> 用报告指导下一轮复习。

第一版的目标不是一次性做完简历管理、JD 追踪、面试复盘、模拟面试和移动端，而是先验证“复习 agent + 可持续知识库”是否真的能提升用户的面试准备效率。

原始想法素材保留在 `docs/my_idea.md`。本文档作为 MVP 开发和后续拆解的产品设计基线。

## 2. 目标用户与核心场景

目标用户是正在准备后端、前端、基础设施、AI 应用、研发工程等技术面试的人。用户手里的资料通常不是完整课程，而是比较随意的内容：

- 自己收集的面试题。
- 零散笔记。
- 半成品答案。
- Markdown、txt、PDF、文档导出件。
- 多轮复习后暴露出的薄弱点。

MVP 要帮助用户持续回答这些问题：

- 我现在最该复习哪些题？
- 我哪些知识点掌握不好？
- 最近一轮我哪些问题答得差？
- 下一轮复习应该怎么安排？
- 这些资料离开 agent 后，能不能在 Obsidian 里继续阅读、编辑和管理？

## 3. MVP 范围

### 3.1 包含范围

- LLM Provider 配置。
- 工作区目录配置。
- 独立 Obsidian Vault 形式的知识库初始化。
- 上传和管理复习资料。
- agent 从零散资料生成结构化题库草稿。
- 用户审核题库后再入库。
- 对话式复习练习。
- 复习前选择主题、难度、题量和模式。
- 对有逻辑关系的问题进行追问。
- 支持从某个问题派生新会话深入讨论。
- 生成单轮掌握度报告。
- 基于最近报告更新全局掌握度报告。
- 所有知识库摄取动作都需要用户确认。
- agent 状态可恢复，会话可继续。
- 展示基础 token 用量和上下文用量。

### 3.2 MVP 不做

- 简历上传、结构化抽取和润色。
- JD 匹配和竞争力分析。
- 按岗位追踪面试准备过程。
- 面试录音转文字后的复盘。
- 模拟面试。
- 语音输入或实时面试模式。
- 微信、飞书等移动端入口。
- 完整知识图谱可视化 UI。
- 未经用户审核的全自动知识入库。

## 4. 产品结构

### 4.1 设置页

设置页负责准备运行环境。

核心能力：

- 配置多个 LLM Provider。
- 支持 OpenAI-compatible 和 Anthropic-compatible API。
- 保存 provider 名称、格式、`base_url`、`api_key`、`model_id`。
- 同一个 provider 下支持多个模型。
- 支持 provider 连通性测试。
- 选择工作区目录。
- 在工作区内初始化或连接已有知识库 Vault。
- 手动触发知识库重新扫描和索引重建。

约束：

- 设置页所有关键动作都要显式。不能在用户不知情的情况下迁移目录、重建数据或自动摄取资料。

### 4.2 复习页

复习页是 MVP 的主工作台。

推荐布局：

- 左侧：复习会话列表。
- 中间：agent 对话与练习区。
- 右侧：状态卡片。

左侧会话列表：

- 展示 agent 自动总结的会话标题。
- 支持普通复习会话。
- 支持从某个问题派生的深入讨论会话。
- 派生会话需要和主复习会话区分，避免污染主线复习上下文。

中间练习区：

- 上传复习资料。
- 展示题库草稿生成过程。
- 开始一轮复习。
- 用户逐题回答。
- agent 评估回答并追问。
- 一轮结束后生成报告。

右侧状态卡片：

- 当前题库。
- 当前复习范围。
- 复习模式和题量。
- token 用量。
- 上下文用量。
- 本轮产出文档。
- 知识库摄取状态。

### 4.3 知识文档页

MVP 不做完整知识图谱 UI，但需要一个实用的知识文档管理页。

核心能力：

- 展示原始资料、题库、复习报告、掌握度报告。
- 展示文档状态：草稿、待审核、已审核、已入库、已过期、已归档。
- 打开生成的 Markdown 文档。
- 对已审核文档触发“确认入库”。
- 用户在 Obsidian 中修改文件后，触发“重新扫描 Vault”。

## 5. 核心复习流程

### 5.1 上传资料

用户动作：

- 上传一份或多份零散复习资料。

系统行为：

- 原始文件保存到 Vault 的 inbox。
- 在 manifest 中创建 source 记录。
- 标记为草稿状态。
- 调用复习 agent 解析内容，生成结构化题库草稿。

输出：

- 原始资料文件。
- 题库草稿。
- 解析摘要，包含重复、歧义、低置信度内容提示。

### 5.2 生成题库

agent 将零散资料整理成结构化问题。

每道题至少包含：

- 稳定 id。
- 标题。
- 主题标签。
- 来源引用。
- 难度。
- 问题正文。
- 参考答案。
- 关键得分点。
- 常见错误。
- 追问问题。
- 相关概念。
- 置信度。
- 审核状态。

用户审核规则：

- 生成题库草稿后不能自动进入正式知识库。
- 用户可以接受、编辑、拒绝，或要求 agent 重写。
- 只有已审核题目可以进入 active review 范围。

### 5.3 设置复习轮次

开始复习前，用户选择：

- 主题范围。
- 题量，例如 10 题或 20 题。
- 难度偏好。
- 复习模式。

复习模式：

- 薄弱点优先。
- 随机混合。
- 单主题巩固。
- 最近错误复现。

agent 可以根据全局掌握度报告推荐模式，但用户可以覆盖。

### 5.4 对话式练习

练习过程中：

- agent 一次只问一道题。
- 用户自由文本回答。
- agent 基于题库、相关概念和历史薄弱点评估回答。
- 如果回答太浅，或题目天然有前后逻辑，agent 可以追问。
- agent 记录最终报告所需的证据。

评估维度：

- 正确性。
- 完整性。
- 表达清晰度。
- 安全推理能力。
- 实际项目关联。
- 常见坑规避情况。

### 5.5 会话派生

如果用户想深入讨论某一道题，可以从当前问题派生新会话。

派生规则：

- 派生会话继承当前问题、相关概念和压缩后的上下文摘要。
- 派生会话不污染主复习轮次。
- 派生会话可以生成修正笔记或题库更新建议。
- 是否把派生产出写入知识库，由用户确认。

### 5.6 单轮掌握度报告

一轮复习结束后，agent 生成单轮掌握度报告。

报告包含：

- session id 和时间。
- 本轮主题范围。
- 已回答问题。
- 表现较好的部分。
- 薄弱部分。
- 不完整答案。
- 重复错误。
- 下一轮建议复习主题。
- 题库更新建议。
- 来自本轮对话的证据片段。

报告初始状态为 `review_pending`。只有用户确认后，才会参与全局掌握度更新。

### 5.7 全局掌握度更新

全局掌握度报告保存长期学习状态。

更新策略：

- 新建复习会话时，agent 读取当前全局报告和最近三份已确认单轮报告。
- 单轮报告确认后，agent 提议更新全局掌握度。
- 如果新旧掌握状态冲突，交给用户选择、合并或编辑。
- 全局报告同时保存为 Markdown 和结构化 metadata，方便人读和机器检索。

## 6. 知识库设计

知识库不是 cyber-interview-agent 的私有数据库，而是一个可以独立使用的 Obsidian-compatible Vault。agent 项目只是它的摄取器、索引器、检索器、练习器和报告生成器。

长期可信数据是 Markdown 文档和 metadata。manifest、索引、关系图、embedding 等都是派生数据，应该可以从 Markdown 和 frontmatter 重建。

### 6.1 第一层：文档层

文档层保存用户可读、可改、可同步、可备份、可迁移的 Markdown 和原始文件。

MVP 推荐目录：

```text
knowledge-vault/
  00_inbox/
  10_question_bank/
  20_review_sessions/
  30_mastery/
  40_concepts/
  80_manifests/
  90_exports/
  .cyber-interview-agent/
```

目录职责：

- `00_inbox/`：上传的原始资料和待处理内容。
- `10_question_bank/`：已审核的结构化题库。
- `20_review_sessions/`：复习会话记录和单轮报告。
- `30_mastery/`：全局掌握度报告和主题掌握度摘要。
- `40_concepts/`：从题目和报告中沉淀出来的概念笔记。
- `80_manifests/`：可读的 manifest 快照，用于审计和迁移。
- `90_exports/`：面向用户导出的文档。
- `.cyber-interview-agent/`：可重建的索引、缓存和内部状态。

### 6.2 第二层：元数据层

Markdown 文件使用 frontmatter 描述状态和关系。metadata 让 Obsidian 和 agent 都能理解文档。

题目 metadata 示例：

```yaml
type: question
id: q_20260709_001
status: reviewed
source_ids:
  - src_20260709_001
topics:
  - backend
  - cache
difficulty: medium
mastery: weak
last_reviewed_at: 2026-07-09
review_count: 2
related_concepts:
  - concept_cache_penetration
related_questions:
  - q_20260709_002
ingestion:
  state: ingested
  confirmed_by_user: true
```

通用文档状态：

- `draft`：导入或生成后尚未审核。
- `review_pending`：等待用户审核。
- `reviewed`：用户已接受。
- `ingested`：已进入检索和复习范围。
- `stale`：文件在索引后发生变化，需要重新扫描。
- `archived`：保留历史，但不参与主动复习。

### 6.3 第三层：索引层

索引层服务机器检索和 agent 推理，属于可重建数据。

MVP 索引：

- manifest index：记录文档 id、路径、类型、状态、版本、checksum。
- keyword index：支持精确搜索和 BM25 类关键词搜索。
- relation index：记录题目、概念、来源、报告和掌握度之间的关系。
- mastery index：记录主题和题目级掌握状态。

embedding index 不作为 MVP 的硬依赖。第一版预留接口，后续在语义检索质量需要提升时再启用。

原则：

- 删除 `.cyber-interview-agent/` 后，系统可以从 Markdown 和 frontmatter 重建索引。
- 索引不应该成为唯一真相。

### 6.4 第四层：关系与掌握度模型

知识库需要追踪的不只是文件，还包括内容之间的关系。

核心关系：

- 原始资料 -> 生成题目。
- 题目 -> 概念。
- 题目 -> 追问。
- 复习会话 -> 已回答题目。
- 复习会话 -> 单轮报告。
- 单轮报告 -> 掌握度更新。
- 掌握度主题 -> 下一轮复习推荐。

掌握状态：

- `unknown`：尚未评估。
- `weak`：明显薄弱。
- `partial`：部分掌握。
- `stable`：稳定掌握。
- `strong`：掌握较好，可以降低复习频率。

掌握状态必须可解释。一个主题被标为 `weak` 时，报告需要能指向具体会话证据，而不是只有 agent 的结论。

## 7. 摄取与查询触发

### 7.1 摄取触发

摄取必须显式、可审计。

触发 1：上传资料

- 保存原始文件。
- 创建 source 记录。
- 生成题库草稿。
- 不自动进入 active review。

触发 2：用户确认题库

- 写入已审核 Markdown。
- 更新 manifest。
- 更新关键词索引和关系索引。
- 将题目标记为 active。

触发 3：用户确认单轮报告

- 报告进入已审核状态。
- agent 提议更新全局掌握度。
- 用户确认后更新 mastery index。

触发 4：用户在 Obsidian 中编辑文件

- app 在启动或手动 rescan 时检测文件变化。
- 变化文件标记为 `stale`。
- 用户触发重新扫描后，系统重新解析 frontmatter 并更新索引。

触发 5：全量重建索引

- 用户在设置页手动触发。
- 用于模型配置变化、schema 升级或索引异常时恢复。

### 7.2 查询触发

查询分为显式和隐式。

显式查询：

- 用户问 agent 某个技术问题。
- 用户搜索题目、主题、薄弱点或来源文件。
- 用户询问当前掌握度。

隐式查询：

- 开始一轮复习。
- 选择下一道题。
- 评估用户回答。
- 决定是否追问。
- 生成单轮报告。
- 更新全局掌握度报告。

所有依赖知识库检索的 agent 结论，都应该在内部保留来源引用；对用户展示时，在必要处显示来源。

## 8. 脱离 Agent 后的 Obsidian 使用能力

Vault 必须能脱离 cyber-interview-agent 单独使用。

只用 Obsidian 也能完成：

- 阅读题库、概念笔记、复习报告、掌握度报告。
- 手动编辑 Markdown 正文。
- 手动修改 frontmatter。
- 使用标签和双链。
- 使用 Obsidian 搜索。
- 配合 Dataview 类插件列出薄弱题目、最近报告、待审核文档。
- 同步、备份、迁移整个 Vault。

离开 agent 后不能完整完成：

- 自动解析新资料。
- 自动生成结构化题库。
- 对话式出题练习。
- 评估用户回答。
- 自动合并单轮报告。
- 语义检索。
- agent 驱动的掌握度更新。

设计原则：

> Obsidian 负责可读、可改、可迁移；Cyber Interview Agent 负责摄取、索引、检索、练习和推理。

## 9. Agent 设计

### 9.1 MVP Agent

MVP 只做一个主 agent：复习 agent。

职责：

- 解析上传资料。
- 生成题库草稿。
- 根据用户反馈修改题库草稿。
- 运行复习轮次。
- 评估回答。
- 发起追问。
- 生成单轮报告。
- 提议全局掌握度更新。
- 必要时解释知识库来源。

### 9.2 工具边界

复习 agent 只能访问用户配置的工作区和 Vault，不能读写沙箱外文件。

MVP 工具：

- 受限文件读写。
- source parser。
- Markdown 生成器。
- manifest updater。
- keyword search。
- relation lookup。
- mastery report reader/writer。
- LLM provider client。

### 9.3 HITL 规则

以下动作必须用户确认：

- 激活生成题目。
- 将 source-derived 内容摄取进知识库。
- 更新全局掌握度报告。
- 覆盖已审核文档。
- 解决冲突掌握状态。
- 归档内容。

以下动作可以不确认：

- 生成草稿。
- 读取 active 知识文件。
- 搜索索引。
- 提议更新。
- 创建临时摘要。

### 9.4 上下文压缩与状态恢复

每个会话都需要可恢复。

持久化状态：

- session id。
- 当前题库。
- 复习模式。
- 已问问题。
- 用户回答。
- agent 评估。
- 上下文摘要。
- 生成文档。
- 待确认动作。

上下文压缩策略：

- 长会话定期摘要。
- 摘要保留已问问题、回答质量、薄弱点和待确认决策。
- 派生会话继承压缩摘要，而不是完整父会话转录。

## 11. 异常处理

Provider 异常：

- 展示连接失败原因。
- 保留当前草稿或会话状态。
- 允许用户切换 provider 或 model。

解析异常：

- 保留原始 source。
- 能部分解析就生成部分草稿。
- 对低置信度内容打标。
- 让用户确认歧义内容。

索引异常：

- Markdown 文档仍是 source of truth。
- 将索引标记为 stale。
- 提供从 Vault 重建索引的入口。

掌握度冲突：

- 展示旧状态、新建议和证据。
- 用户选择、合并或编辑。

文件冲突：

- 通过 checksum 或 modified time 检测外部编辑。
- 不静默覆盖已审核文件。
- 必要时保存 conflict copy。

## 12. 成功指标

产品指标：

- 用户能完成 provider 和 workspace 配置。
- 用户能导入零散资料并生成已审核题库。
- 用户能完成一轮 10 题复习。
- 用户能拿到有用的单轮掌握度报告。
- 确认报告后，全局掌握度能被更新。
- 用户能在 Obsidian 中打开并理解生成文件。
- 删除派生索引后，系统能从 Markdown 重建。

质量指标：

- 生成题目保留来源引用。
- agent 评估包含具体证据。
- 用户确认点清晰。
- 不会自动污染知识库。
- 重启后可恢复会话。

## 13. Post-MVP Roadmap

### 阶段 2：个人信息中心

- 简历上传和删除。
- 结构化个人画像抽取。
- 简历评估和润色建议。
- 用户确认后再应用修改。
- 管理 GitHub 贡献、技术博客、研究内容、项目说明等资料。
- 个人资料是否进入知识库，由用户审核决定。

### 阶段 3：JD 与岗位追踪

- 上传 JD 和公司信息。
- 按岗位追踪准备过程。
- 基于 JD、简历和知识库做匹配分析。
- 生成竞争力分析。
- 将复习计划绑定到目标岗位。

### 阶段 4：面试复盘

- 导入面试转写文本。
- 清理转写内容，必要时倒推面试官问题。
- 分析答得好和答得不好的地方。
- 提炼项目经验。
- 用户审核后将复盘产出写入知识库。

### 阶段 5：模拟面试

- 载入 JD、简历、题库和知识库上下文。
- 支持技术面和 HR 面。
- 使用固定题量或用户主动结束，不以时间作为主要结束条件。
- 支持恢复和继续。
- 面试结束后生成总结文档。

### 阶段 6：移动端入口

- 微信和飞书入口。
- 每日轻量复习。
- 快速答题。
- 面试后快速记录。
- 查看薄弱点和下一步复习建议。

## 14. MVP 默认决策

- MVP 默认不依赖 embedding，先做关键词检索、manifest、关系索引和掌握度索引。
- Markdown 模板至少包括 question、concept、session report、mastery report。
- 知识文档页第一版可以是文件列表 + 状态 + 操作按钮，不强求图谱 UI。
- API key 需要加密存储。MVP 默认优先使用系统密钥链；如果运行环境不支持系统密钥链，再使用工作区外的本地加密配置文件。
- 第一版优先支持 Markdown、txt 和可提取文本的 PDF。复杂 Office 文档解析放到后续。
