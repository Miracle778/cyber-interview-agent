# Cyber Interview Agent 产品布局重构设计

## 1. 背景

当前前端把设置、资料上传、知识扫描和单题复习依次堆叠在一个页面中。这种结构适合验证最小技术链路，但不适合产品的最终形态：复习、个人资料、岗位追踪、面试复盘和模拟面试将分别拥有长期会话、上下文、产物和待确认动作，设置也不应继续作为每次使用的第一步。

本次重构在 R1.2 Agent Runtime 与 SSE 之前完成，为后续业务页面建立稳定的信息架构和响应式应用骨架。重构只调整前端组织与体验，不新增后端能力，也不制作尚未实现的业务空壳。

## 2. 目标

- 把现有单页技术演示改造成可持续扩展的产品工作台。
- 为当前真实功能提供独立 URL、稳定导航和清晰页面职责。
- 为后续 Agent 页面的“会话列表 / 对话 / 上下文与动作”结构预留布局能力。
- 保留 Workspace 恢复、资料上传、题库草稿、单题复习、报告确认、Provider 和模型绑定等现有行为。
- 桌面、平板和手机均无横向溢出，核心操作可通过键盘访问。

## 3. 非目标

- 不实现 R1.2 的 Session、Run、SSE 或 Checkpoint。
- 不实现个人资料、岗位追踪、面试复盘或模拟面试页面。
- 不创建只显示“开发中”的未来功能页面。
- 不重写后端 API，不改变现有数据模型。
- 不在本次加入深色模式、复杂动效或营销式首页。

## 4. 信息架构

### 4.1 最终产品层级

最终一级业务能力为：

1. 首页：待办、最近会话、待确认动作和准备状态。
2. 复习：题库、复习会话、回答评估和掌握度。
3. 个人资料：简历、项目经历、技能和个人画像。
4. 岗位：JD、匹配分析和岗位维度的准备资产。
5. 面试复盘：真实面试记录、问题还原和经验沉淀。
6. 模拟面试：技术面、HR 面和岗位定向模拟。
7. 知识库：资料、草稿、已发布知识和索引状态。
8. 设置：Workspace、Provider、模型绑定和运行环境。

本次只展示已经可操作的入口：复习、知识库和设置。首页不制作独立空壳，根路径直接进入复习；未来首页具备真实聚合数据时再加入导航。

### 4.2 当前路由

| URL | 页面 | 职责 |
| --- | --- | --- |
| `/review` | 复习 | 单题复习、评估和报告确认 |
| `/knowledge` | 知识库 | 上传资料、查看题库草稿和重建索引 |
| `/settings` | 设置 | Workspace、Provider、模型和用途绑定 |
| `/` | 重定向 | 重定向到 `/review` |
| 其他路径 | 兜底 | 重定向到 `/review` |

每个关键页面都能通过 URL 直接访问。浏览器前进和后退必须保持可预测，路由变化后主内容获得语义明确的页面标题。

## 5. 应用骨架

### 5.1 桌面端

宽度大于等于 1024px 时采用固定双区结构：

- 左侧 240px 导航栏：品牌、主要功能、系统状态和设置入口。
- 右侧主区域：页面顶栏和页面内容。
- 主内容使用响应式宽度，不再被旧的 880px 单列容器限制。
- 设置页内容最大宽度约 1120px；普通业务页最大宽度约 1280px。

导航分为“工作台”和“系统”两组。复习、知识库属于工作台；设置位于系统组，避免和高频业务入口混在同一层级。

### 5.2 移动端与平板

宽度小于 1024px 时：

- 隐藏常驻侧栏，显示紧凑顶部栏。
- 左上角菜单按钮打开模态抽屉，抽屉包含与桌面一致的导航和状态。
- 抽屉打开后锁定背景滚动，支持点击遮罩、关闭按钮和 Escape 退出。
- 路由切换后自动关闭抽屉。
- 所有按钮和导航项拥有至少 44px 的可点击高度。

不使用底部导航，因为最终一级功能会超过五个；抽屉更适合未来的完整功能集合。

### 5.3 页面顶栏

每个页面显示：

- 页面名称。
- 一句短描述，说明当前页面对象，不写使用教程。
- 右侧 Workspace 状态和后端连接状态；窄屏时状态换行。

后端断开使用明确错误状态；Workspace 未配置使用中性状态。状态不仅依赖颜色，还包含图标和文本。

## 6. 页面布局

### 6.1 复习页

当前阶段采用两列工作区：

- 主列：当前题目、回答输入、评估和报告确认。
- 右侧 300px 上下文栏：当前题库草稿、Workspace、流程状态和下一步动作。

在 R1.2/R1.6 中升级为三栏 Agent 工作区：左侧会话列表、中间对话、右侧上下文与待确认动作。当前组件边界不得阻碍这一升级。

没有题库草稿时，页面给出明确空状态，并提供前往知识库的真实导航动作。

### 6.2 知识库页

页面分为：

- 顶部操作区：资料上传与重新扫描。
- 内容区：当前生成的题库草稿或空状态。
- 状态区：当前 Workspace、Vault 和索引结果。

没有 Workspace 时，提供前往设置的动作；不要求用户在同页向上寻找设置表单。

### 6.3 设置页

设置页不再占据默认入口。页面内部按职责分组：

- Workspace。
- Provider 与模型。
- 模型用途绑定。

保留现有表单行为和错误反馈。长列表保持普通文档流，不制造嵌套滚动区域。

## 7. 状态与数据流

本次继续由顶层应用状态保存当前 Workspace、题库草稿、最新报告和索引数量，以保持现有跨页面链路。路由只负责页面选择，不复制业务状态。

- 初始化 Workspace 后，所有页面立即获得新 Workspace。
- 上传资料后，生成的题库草稿可在复习页使用。
- 复习报告生成和确认状态在当前浏览器会话内保留。
- 刷新后的 Workspace 继续从后端恢复。
- 题库草稿和报告在刷新后丢失仍是现有 R0 边界，后续由 R1.2/R1.6 的持久化 Session 取代。

## 8. 视觉系统

产品定位是安静、专业、内容优先的个人工作台，不采用营销页、游戏化或强烈“AI 紫色”表达。

- 使用浅灰白画布、白色工作表面、深色正文。
- 主色采用克制的靛青，用于当前导航、主要按钮和焦点环。
- 成功、警告、错误使用独立语义色，并始终搭配文字或图标。
- 卡片圆角不超过 8px，减少漂浮卡片感；页面分区优先使用留白和分隔线。
- 沿用 Lucide 图标，保持统一线性风格。
- 正文字号至少 16px；辅助文字不低于 13px。
- 交互动效控制在 150-250ms，只表达抽屉、焦点和状态变化。
- 支持 `prefers-reduced-motion`。

设计 token 统一定义颜色、间距、边框、阴影、层级、内容宽度和动效，组件中不新增零散颜色值。

## 9. 可访问性与响应式要求

- 正文对比度至少 4.5:1，非文本控件至少 3:1。
- 所有表单使用可见 label，错误信息靠近相关操作并使用 `aria-live`。
- 当前导航使用 `aria-current="page"`。
- 移动菜单按钮、关闭按钮使用明确 accessible name。
- 抽屉打开时焦点进入抽屉，关闭后返回菜单按钮。
- 页面可完全通过键盘操作，焦点环不可移除。
- 在 375、768、1024 和 1440px 验证，无水平滚动和内容遮挡。

## 10. 组件边界

新增或调整以下前端边界：

- `AppRouter`：声明路由和重定向。
- `AppShell`：恢复全局状态并组合响应式骨架。
- `PrimaryNavigation`：共享桌面与移动导航数据和语义。
- `MobileNavigation`：管理抽屉打开、关闭和焦点行为。
- `PageHeader`：页面标题、描述和全局状态。
- `FlowSummary`：当前 R0 流程状态，作为复习页辅助信息，不再全局占据每个页面。
- 现有 `SettingsPage`、`KnowledgePage`、`ReviewPage`：继续拥有各自业务交互。

导航项使用单一配置源，桌面和移动渲染共享语义，避免未来新增业务入口时出现两套列表漂移。

## 11. 测试与验收

### 11.1 自动测试

- 路由：根路径重定向、三个页面可直接访问、未知路径兜底。
- 导航：当前项状态、桌面导航、移动抽屉打开与关闭。
- 状态：后端连接、Workspace 恢复和跨路由题库草稿传递。
- 回归：设置、知识库和复习现有组件测试继续通过。
- 构建：TypeScript 和 Vite production build 通过。

### 11.2 人工验收

1. 打开根路径后进入复习页，不再同时看到三大功能表单。
2. 通过侧栏分别进入知识库和设置，URL 与当前导航同步。
3. 初始化 Workspace、上传资料，再返回复习页完成现有单题链路。
4. 在 1440px 检查侧栏、页面顶栏和双列复习布局。
5. 在 768px 和 375px 检查移动菜单、抽屉、表单和内容换行。
6. 使用键盘完成导航、打开/关闭抽屉和主要表单操作。
7. 模拟后端断开，确认全局状态和页面错误提示明确。

## 12. 完成定义

- 当前三个真实功能被拆成独立路由和清晰页面。
- 桌面侧栏与移动抽屉使用同一导航定义，行为一致。
- 旧的三步进度条和单页堆叠结构被移除。
- 现有业务闭环没有因布局重构而退化。
- 自动测试、构建和多视口浏览器验收均通过。
- R1.2 可以在复习页中接入 Session、Run、SSE，而无需再次推翻全局导航和页面骨架。
