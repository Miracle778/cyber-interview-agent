# Pre-R2 页面与知识库体验稳定化设计

> **历史实现记录，禁止作为后续模板：** 本文保留 Pre-R2 当时的体验决策与验收事实。
> 其中对 Runtime Middleware 1.0、自研 pipeline 或旧 Agent API 的后续安排已由
> `docs/superpowers/specs/2026-07-13-agent-runtime-framework-convergence-design.md` 取代。
> R2-R8 必须以产品总路线、框架收敛设计和各阶段新 spec 为准；本文的 UI、知识草稿、
> Markdown 和按需人工确认原则仍可作为历史证据。

## 1. 背景与决策

R1 已打通工作区、Provider、Agent Runtime、知识草稿发布和单题复习，但页面仍以功能卡片纵向平铺。知识库没有持久化展示原始上传资料，Markdown 在非编辑状态下仍以原文显示，人工确认区域在没有待确认动作时也占据页面空间。

这些问题会干扰 R2 多题复习和题库管理继续扩展，因此在 R2 前增加一个体验稳定化切片。R1.2 未完成的上下文压缩与 token/context 用量记录属于独立 Runtime 基础能力，不与本切片混合实现；它在本切片之后、R2 之前单独补齐。

## 2. 目标

- 将知识库从卡片流调整为内容优先的资源工作区。
- 持久化并展示已上传的原始资料，而不是只展示当前内存中的题目。
- 区分 Markdown 阅读态和编辑态，默认展示渲染结果。
- 仅在存在待确认动作或正在等待动作产生时展示人工确认区域。
- 调整复习页的信息层级，为 R2 扩展留出稳定结构，但不增加 R2 功能。
- 保持桌面端、平板和 375px 移动端可用，保留键盘访问和清晰焦点状态。

## 3. 非目标

- 不实现 R2 的多题复习、选题策略、会话报告聚合或全局掌握度。
- 不改变知识草稿发布状态机、安全边界和 Vault 写入规则。
- 不在本切片实现上下文压缩、token 计量或 Provider 用量统计。
- 不引入完整知识图谱、全文检索、资料删除或批量操作。
- 不修改 `docs/my_idea.md`。

## 4. 信息架构

### 4.1 知识库

桌面端采用三段式工作区：

1. **资源导航区**：分为“原始资料”和“生成草稿”两个分组。
2. **内容区**：显示当前选中项的阅读视图；草稿可进入显式编辑模式。
3. **上下文确认区**：仅在知识发布动作待确认或正在等待动作生成时出现。

上传和重新扫描是知识库级操作，放在页面工具栏，不再作为与内容并列的大卡片。没有资源时，内容区显示带明确上传入口的空状态。

移动端按内容优先顺序纵向排列：页面工具栏、资源选择、内容、按需确认。不得产生整页横向滚动或固定宽度侧栏。

### 4.2 复习页

复习页保留现有单题行为，只重排为：

1. 会话选择与当前复习上下文。
2. 当前题目、回答输入和对话记录。
3. 已生成的复习报告。
4. 桌面端右侧状态摘要；移动端置于主要练习内容之后。

发布审批继续只在 `pending` 状态出现。不得在本切片添加题目数量、复习模式、难度筛选或下一题逻辑。

## 5. 数据与接口

### 5.1 原始资料资源

新增可持久化的 source metadata，至少包含：

- `id`
- `workspaceId`
- `originalFilename`
- `storedPath`
- `contentType`
- `sizeBytes`
- `createdAt`
- 关联草稿 ID（存在时）

上传成功时，原始文件与 metadata 必须作为同一业务操作完成；若 metadata 写入失败，不得向前端报告完整成功。文件继续存放在 `artifacts/review/sources/`，所有路径仍经过 Workspace 路径策略校验。

新增按工作区列出资料的只读接口。返回值不得泄露工作区之外的绝对路径，只暴露工作区相对路径和用户可读的原始文件名。

### 5.2 前端数据流

- 页面进入时并行读取 source 列表、draft 列表和 pending knowledge publication actions。
- 上传成功后同时刷新 source 与 draft 查询，自动选中新上传资料关联的草稿。
- 选中原始资料时显示文件信息、来源路径和关联草稿入口，不直接把任意本地文件内容注入浏览器。
- 选中草稿时显示 Markdown 阅读视图及状态、版本、发布路径和索引状态。
- 编辑模式是草稿详情的局部状态；保存成功后退出编辑态并刷新服务端版本。

## 6. Markdown 阅读与编辑

- 默认阅读态使用受控 Markdown 渲染器，支持标题、段落、列表、强调、引用、代码块和链接。
- 不启用原始 HTML 渲染，避免草稿内容注入脚本或危险节点。
- 外部链接使用安全属性，并保持键盘可访问。
- 只有可编辑状态的草稿显示“编辑”动作；进入编辑态后展示标题输入框和 Markdown textarea。
- `published` 和 `rejected` 草稿保持只读；现有状态机规则不改变。
- 取消编辑恢复最近一次服务端内容；存在未保存修改时需要确认，避免误丢内容。

## 7. 人工确认的渐进披露

- `ActionCenter` 在无动作、非诊断模式且没有 `watchRunId` 时返回 `null`，不渲染空卡片。
- 请求发布后，在等待 pending action 产生期间显示紧凑加载区域，避免用户误以为请求丢失。
- pending action 出现后显示确认详情、可编辑字段、批准和拒绝操作。
- 动作解决后立即移除确认区域，并刷新草稿与 pending action 查询。
- 设置页的 Runtime/HITL 诊断入口保持原行为，可继续显示“暂无待确认动作”。

## 8. 视觉与交互规则

本切片沿用现有语义色和组件体系，不进行品牌重做。按 `ui-ux-pro-max` 的内容优先与渐进披露建议执行：

- 一个页面只保留一个最高强调级主操作；上传为知识库主操作，重新扫描为次级操作。
- 桌面侧栏和内容区宽度使用响应式网格；长 Markdown 的正文宽度限制在可读范围。
- 所有按钮和列表项具有可见 hover、pressed、focus 和 disabled 状态。
- 交互目标不小于 44px，正文对比度满足 WCAG AA。
- 动效只用于面板出现和状态切换，时长 150–300ms，并尊重 `prefers-reduced-motion`。
- 使用现有 Lucide 图标，不使用 emoji 作为结构图标。

## 9. 错误处理

- source 列表加载失败时保留上传工具栏，内容区显示原因和重试入口。
- 上传失败不得插入虚假的本地列表项；错误继续转换为可执行建议。
- Markdown 渲染失败时退化为安全纯文本，不暴露空白区域。
- 草稿版本冲突继续自动刷新，并明确提示用户重新检查内容。
- pending action 轮询失败时展示错误与重试入口，但不得永久保留无反馈的加载状态。

## 10. 测试与验收

### 10.1 后端针对性测试

- 上传后 source metadata 可重启恢复并保留原始文件名。
- 列表接口仅返回当前工作区资料，且路径为安全相对路径。
- 超限文件、非法文件名和 metadata 写入失败保持原子性。

### 10.2 前端针对性测试

- 知识库展示持久化的“原始资料/生成草稿”分组。
- 上传成功后两个分组刷新并选中新草稿。
- 草稿默认渲染 Markdown，进入编辑后才显示原文 textarea。
- 没有待确认动作时不出现“人工确认”；请求发布和 pending 状态出现时才显示。
- 复习页行为与现有单题测试保持一致，只验证结构和响应式语义未回退。

### 10.3 浏览器验收

- 最小 happy path：上传资料 → 看见资料和草稿 → 阅读渲染内容 → 编辑保存 → 请求发布 → 人工确认出现并解决。
- 完整验收：桌面与 375px 移动端、页面刷新、后端重启恢复、键盘操作和无横向滚动。
- 完成针对性测试后只运行一次最终前后端全量回归、build 和文档门禁。

## 11. 阶段顺序与完成边界

1. 完成本设计对应的 UI/知识库体验稳定化。
2. 独立设计并补齐 Runtime Middleware 1.0：pipeline 契约/注册/顺序/开关、R1.2 上下文压缩与 context budget、token/context 用量、会话标题、无限循环检测、HITL adapter，以及 OpenTelemetry 抽象 + 本机 Langfuse 调试链路；只定义 `TodoCandidate` 契约，不实现提取与正式 Todo Service。使用 R1.6 `review.single` 完成真实 Agent 验收。
3. 两个 Pre-R2 切片验收后开始 R2。

本切片完成不代表 R1.2 Runtime 债务已经清偿，也不代表 R2 已开始。
