# Workspace 历史复盘检索与总结报告设计

## 1. 背景

单场面试复盘已经可以从准确转写、问题提取进入逐题分析与讨论，但用户在积累多场复盘后，仍无法回答下面这类 Workspace 级问题：

- 之前所有关于某个项目的问题有哪些；
- 哪些追问在不同面试里反复出现；
- 最近几次面试在同一能力点上是否有改善；
- 把当前检索结果整理成可长期复用的专项总结报告。

现有“讨论与纠正”只允许读取当前复盘，不能扩大为跨复盘入口。历史检索必须建立独立的 Workspace 级只读边界，同时保留每条结论到具体复盘、题目和回答证据的可追溯关系。

## 2. 产品目标

在“面试复盘”一级页面内新增两个并列模式：

1. `复盘记录`：保留当前生命周期管理与单场复盘入口；
2. `历史检索`：跨当前 Workspace 的正式复盘题目、回答证据与分析结论进行检索。

历史检索支持：

- 自然语言查询与显式筛选；
- 展示确定性的命中总数；
- 按面试场次分组浏览；
- 回到具体题目或具体复盘；
- 对当前结果集进行即时总结；
- 将当前结果集生成持久化、可编辑、可追溯的总结报告；
- 查看历史报告及其生成范围。

## 3. 明确不做

首版不做：

- 让模型直接扫描 Workspace 中的全部长转写；
- 让自由 ReAct Agent 自行判断是否“已经找全”；
- 搜索未确认的推断题、已拒绝题或已被替代题；
- 搜索回收站复盘；
- 向题库、画像、项目资料或 Knowledge 自动写入；
- 自动联网扩展项目知识；
- 无来源引用的跨场次结论；
- 向量数据库或外部搜索服务依赖。

## 4. 用户体验

### 4.1 历史检索首页

页面顶部提供：

- 自然语言输入框；
- 求职目标、公司、岗位、轮次、日期、题目来源筛选；
- 搜索按钮；
- 历史报告入口。

搜索完成后显示：

- `在 N 场面试中找到 M 道相关问题`；
- 当前检索范围和筛选条件；
- 按面试场次分组的结果；
- 每条结果的问题文字、来源类型、分析结论、短回答证据和命中词；
- `查看该题`、`打开本场复盘`；
- `总结这些问题`、`生成报告`。

### 4.2 即时总结

即时总结属于当前搜索结果集，不创建正式报告。用户可继续追问：

- 只总结回答不好的部分；
- 找出跨面试重复问题；
- 按项目架构、职责和业务价值分类；
- 给出下一轮准备清单。

总结中的每个主题必须引用至少一个命中题目，前端允许展开来源。

### 4.3 总结报告

报告创建前允许选择：

- 报告名称；
- 全部结果或已选结果；
- `问题汇总`、`表现复盘`、`专项准备`侧重点；
- 是否包含回答摘录；
- 是否包含行动清单。

报告固定包含：

1. 检索范围；
2. 核心结论；
3. 问题主题；
4. 回答表现；
5. 高频问题；
6. 推荐准备；
7. 来源附录。

报告保存为 Workspace 私有版本化 Artifact。报告正文允许用户编辑；重新生成只创建新版本，不覆盖旧版本。

## 5. 检索 Agent 边界

历史检索使用有界工具型 Agent，不使用自由 ReAct。

固定阶段：

```text
PARSE → SEARCH → FETCH_DETAILS（可选）→ ANSWER
```

Agent 负责：

- 把自然语言转成结构化 `SearchPlan`；
- 补充少量项目别名和技术术语；
- 在已有结果集上生成带引用总结；
- 在冻结结果集上生成报告。

确定性程序负责：

- Workspace、生命周期和题目正式状态过滤；
- 计算命中、排序、总数与分页；
- 固化结果集和结果顺序；
- 校验总结与报告引用只来自当前结果集；
- 保证“所有”表示完整扫描当前正式检索语料，而不是模型记忆。

Agent 只拥有以下只读能力：

- `search_retrospective_questions`；
- `read_retrospective_search_result`；
- `list_retrospective_projects`。

首版固定 Workflow 可直接调用同一底层检索服务，不要求模型自由选择 Tool；Trace 仍按 Agent Operation 展示解析、检索、总结和报告生成。

## 6. 检索语料与相关性

### 6.1 可检索题目

- `origin=original` 且未被拒绝或替代；
- `origin=inferred` 且 `decision_status=confirmed`；
- 所属复盘生命周期为 `active` 或 `archived`；
- 所属分析运行存在正式逐题结果；
- 回收站、失败且无正式分析结果的复盘不进入语料。

### 6.2 索引字段

- 题目文字；
- 回答证据短摘录；
- 优点、改进点、遗漏与建议回答结构；
- 公司、岗位、轮次、复盘标题；
- 项目名称与检索计划提供的别名；
- 稳定的 retrospective/question/analysis ID。

### 6.3 首版评分

首版采用本地、可解释的加权词法评分：

1. 题目精确短语命中；
2. 项目名或别名命中；
3. 技术缩写或关键词命中；
4. 回答证据命中；
5. 分析字段命中；
6. 相同得分按面试日期、题目序号和稳定 ID 排序。

模型产生的搜索词只是候选条件，显式 UI 筛选不能被模型放宽。首版不宣称同义语义召回完整；后续只有在真实漏召回样本证明词法检索不足时，才在确定性候选集上增加语义重排。

## 7. 持久化模型

### 7.1 Search Set

`interview_retrospective_search_sets` 保存：

- Workspace、查询正文、结构化 SearchPlan；
- 显式筛选；
- 状态、命中题目数、命中复盘数；
- Agent Execution ID；
- 创建和完成时间。

### 7.2 Search Result

`interview_retrospective_search_results` 保存：

- Search Set ID；
- retrospective/question/analysis ID；
- 稳定排序、分数、命中词；
- 搜索时的问题、回答与分析短快照；
- 来源元数据快照。

结果快照保证后续总结、报告和对话指代不会因原题编辑或上下文压缩而漂移。

### 7.3 Search Report

`interview_retrospective_search_reports` 保存：

- Workspace、Search Set ID、标题、侧重点；
- 选中结果 ID；
- 报告结构化正文与 Markdown；
- 引用题目 ID；
- Execution ID、状态和版本；
- 创建、完成和更新时间。

## 8. 长结果集处理

结果集正文不能一次全部送给模型。即时总结和报告均采用固定 Map-Reduce：

1. 每批读取有界题目、回答证据和分析摘要；
2. 每批生成只引用本批题目的主题摘要；
3. Reduce 只读取批次摘要和稳定题目 ID；
4. 程序拒绝不属于 Search Set 的引用；
5. 报告来源附录由程序生成，不由模型自由编写。

如果某批失败，保留已完成批次并允许恢复；报告不能以部分成功伪装成完整成功。

## 9. 隐私与删除

- 数据严格按 Workspace 隔离；
- Search Agent 不读取画像、简历、岗位原文或其他 Workspace；
- 默认只保存题目和有界回答/分析摘录，不复制完整转写；
- 清除复盘原文后，结果快照中的回答摘录同步清除或标记不可用，题目和结构化分析可继续保留；
- 永久删除复盘时，Search Result 来源行级联删除；关联报告标记来源缺失，不伪造完整引用；
- 报告导出遵守本地数据边界，不自动发布到 Knowledge。

## 10. 错误与恢复

- 查询解析失败：回退到用户原始查询的确定性词法检索；
- 无结果：保留 Search Set，显示可调整的筛选与检索词；
- 总结失败：检索结果仍然可用，可单独重试总结；
- 报告失败：保留草稿记录和结果集引用，可从失败阶段恢复；
- 来源已删除：显示来源不可用，不删除用户已编辑的报告正文；
- Provider 未配置：确定性检索仍可用，只禁用智能总结和报告生成。

## 11. 验收标准

1. 历史检索位于“面试复盘”内，不增加一级导航；
2. 查询只返回当前 Workspace 的正式题目；
3. 未确认推断题、拒绝题、替代题和回收站复盘不进入结果；
4. 命中总数和分页由程序确定；
5. 每条结果可定位到具体复盘和题目；
6. 搜索结果在刷新后保持稳定；
7. “总结这些问题”只引用当前 Search Set；
8. 报告保存为独立版本化 Artifact；
9. 大结果集分批处理，不把全部正文一次送入模型；
10. Provider 不可用时仍可搜索；
11. 清除原文和永久删除不会留下误导性的可用证据；
12. Agent 运行中心能看到搜索解析、总结和报告生成的真实 Execution。
